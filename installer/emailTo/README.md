# emailTo — stand-alone installer

`emailToSetup.exe` installs the emailTo template set into as many Clarion installations as you
tick, **Clarion 10 forward**, and registers it in each one with that installation's own
`ClarionCL`.

    pwsh installer\emailTo\build-emailTo.ps1        ->  installer\emailTo\Output\emailToSetup.exe

It needs [Inno Setup 6](https://jrsoftware.org/isdl.php). `payload\` and `Output\` are build
artifacts and are not committed.

## What it puts where

Into every ticked Clarion installation:

| | |
|---|---|
| `accessory\template\win\emailTo.tpl` | the ten templates |
| `accessory\libsrc\win\Email*.inc/.clw` | the six classes |
| `accessory\libsrc\win\emailc.c` | sockets, SCHANNEL TLS, WinHTTP, DPAPI, SHA-256 |

and then `ClarionCL /tr` on the deployed path — registering from anywhere else makes the control
templates resolve against that other folder.

Beside them, in the program folder: the manual (four volumes × two languages), the dictionary to
import, the demo sources and this read-me.

## The two builds of the template

AppGen draws a template's prompt sheet in a dialog whose width belongs to the IDE, not to the
template: **480 px up to Clarion 10, 960 px from Clarion 11** (`WideAppgenDialogs` in
`ClarionProperties.xml`). A prompt sheet is parsed once, at registration, and there is no template
symbol for "how wide am I being drawn?" — so the installer ships both and picks by version:

* Clarion 11, 11.1, 12 and later → `emailTo.tpl` as written
* Clarion 10 and older → the build generated by `templates\emailTo\Build-NarrowTpl.ps1`,
  its prose re-wrapped to 340 px and eleven captions shortened to fit the 200 px label column

Both declare `#TEMPLATE(emailTo,...)` and both are installed **as `emailTo.tpl`**. The generator's
self-check strips both files of exactly their `#DISPLAY` text and `#PROMPT` captions and demands
the remainder be byte-identical, so an application moves between a Clarion 10 machine and a
Clarion 12 one and generates the same code. `build-emailTo.ps1` re-runs that generator every time
and refuses to build the installer if anything has grown past what 480 px can draw.

## Finding the installations

Two sweeps, merged and de-duplicated, each entry verified by `bin\ClarionCL.exe` +
`accessory\template\win` and its version read off `ClarionCL.exe`:

1. every version the IDE knows — the `<path value="...\bin">` entries in
   `%APPDATA%\SoftVelocity\Clarion\*\ClarionProperties.xml`
2. `Clarion*` folders on every **fixed** drive root and under `SoftVelocity\` in Program Files

Anything below Clarion 10 is ignored. **Add an installation…** takes one the sweeps missed (a
network drive, an unusual name).

If the Clarion IDE is running the wizard says so and offers to wait: the IDE holds the template
registry open and writes it back when it closes, which can undo a registration made behind it.

## Command line

    emailToSetup.exe /VERYSILENT /CLARION="C:\Clarion12|C:\Clarion11"
    emailToSetup.exe /VERYSILENT /CLARION=all

`/CLARION` takes `all` or a `|`-separated list of installation folders, and adds any that the
sweeps did not find. **A silent run with no `/CLARION` installs the files but touches no Clarion
installation** — a machine can carry a dozen Clarion folders, and an unattended installer has no
business guessing which of them wants a template registered into it.

## Uninstalling

Uninstall offers to remove emailTo from each installation it went into. It unregisters with
`ClarionCL /tu emailTo` — **the chain name, not the path**: handed a path, even the exact path
`/tr` was given, `/tu` answers *"Template chain is not found"* and unregisters nothing. If `/tu`
fails, that installation's files are deliberately left in place: deleting a `.tpl` that is still
registered leaves the installation reporting *"Could not open include file emailTo.tpl"* on every
generate, and the way out of that is to restore the file and unregister properly.
