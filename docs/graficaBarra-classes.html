13 types · 48 categories × 8 series · window + report · vector PDF · pure Clarion

OverviewResumen

One object is one chart. You fill it with data, set a handful of properties, and call one method — Draw on a window, Paint on a report. Everything is drawn with Clarion's own graphics statements (BOX, LINE, POLYGON, ELLIPSE, PIE, SHOW), so there is no bitmap, no DLL and no external dependency, and a report keeps the chart as vector primitives — the PDF stays small.

This page is the deep reference for driving the class from code. If you are looking for the AppGen prompts, see the template page; for the concepts (scale, coordinates, window vs report) see the developer's reference.

Object modelModelo del objeto

What it owns, what it only borrows

The class is deliberately small and self-contained. It owns its data and its settings; it borrows the drawing target for the duration of one call and gives it back.

OwnsBorrows
  • The category × series grid (labels, values, colours)
  • Every visual setting — ChartType, colours, flags
  • Scratch buffers for POLYGON and PIE
  • The draw state (z… fields) computed fresh on each Paint
  • The current target — it draws wherever SETTARGET points
  • The target's font, read with GETFONT(0,…) and restored at the end
  • The placeholder control's rectangle, read with GETPOSITION
  • The pen — it sets colour, width and style, and does not restore them

It never creates a control, never opens a window, never allocates memory, and has no Destruct. A chart on a report adds ink to the band, not controls — the ReportClear demo proves it by walking PROP:NextField before and after a Paint and finding the same control census both times.

Fixed storage, no allocation

All storage is DIM'd in the class, so one instance is a fixed block of about 6.5 KB. That is the number to keep in mind if you NEW a dashboard's worth of them.

EquateValueWhat it caps
GraficaBarra:MaxBars48Categories, pie slices, line points, radar axes
GraficaBarra:MaxSeries8Series
GraficaBarra:MaxSeries27Storage for series 2…8 (see the data grid)
GraficaBarra:MaxPoly200POLYGON scratch = 100 corners
GraficaBarra:Pi3.14159265358979Pie and radar angles
Why 100 polygon corners is enough. The greediest shape is a stacked area band: it walks the categories forward along its own top edge and back along the one below, so 2 × 48 = 96 corners — four to spare. Raise MaxBars and you must raise MaxPoly to at least 4 × MaxBars + 8 with it, or PolyAdd starts dropping corners silently (GraficaBarraClass.clw:334).

Non-virtual by design

No method carries the VIRTUAL attribute. A derived class can add methods and can replace one, but the replacement is not called from inside the base — Paint will still call the base PaintBars. To customise the drawing, either edit the class or wrap it (see Extending the class).

Qué posee y qué solo toma prestado

La clase es deliberadamente pequeña y autocontenida. Posee sus datos y sus ajustes; toma prestado el destino de dibujo durante una llamada y lo devuelve.

PoseeToma prestado
  • La rejilla categorías × series (etiquetas, valores, colores)
  • Cada ajuste visual — ChartType, colores, banderas
  • Búferes de trabajo para POLYGON y PIE
  • El estado de dibujo (campos z…) recalculado en cada Paint
  • El destino actual — dibuja donde apunte SETTARGET
  • La fuente del destino, leída con GETFONT(0,…) y restaurada al final
  • El rectángulo del control marcador, leído con GETPOSITION
  • La pluma — fija color, grosor y estilo, y no los restaura

Nunca crea un control, nunca abre una ventana, nunca reserva memoria y no tiene Destruct. Un gráfico en un informe agrega tinta a la banda, no controles — la demo ReportClear lo prueba recorriendo PROP:NextField antes y después de un Paint y encontrando el mismo censo de controles.

Almacenamiento fijo, sin reservas

Todo el almacenamiento está DIMensionado en la clase, así que una instancia es un bloque fijo de unos 6,5 KB. Es la cifra a tener presente si hace NEW de varios para un tablero.

Por qué bastan 100 esquinas. La figura más golosa es una banda de área apilada: recorre las categorías de ida por su borde superior y de vuelta por el de abajo, o sea 2 × 48 = 96 esquinas — sobran cuatro. Si sube MaxBars, suba también MaxPoly a por lo menos 4 × MaxBars + 8, o PolyAdd empezará a descartar esquinas en silencio (GraficaBarraClass.clw:334).

No virtual, a propósito

Ningún método lleva el atributo VIRTUAL. Una clase derivada puede agregar métodos y puede reemplazar uno, pero el reemplazo no se llama desde dentro de la base — Paint seguirá llamando al PaintBars base. Para personalizar el dibujo, edite la clase o envuélvala (vea Extender la clase).

In a multi-DLL application

The class is a plain CLASS,TYPE,MODULE(…),LINK(…), so it follows the usual rules: it must be compiled into exactly one project of the chain and exported from there. The template's global extension registers it with an ABC class category, which makes the chain write the pragmas and the mangled .EXP entries for you. Hand-coded, add to the DLL that owns it:

  PRAGMA('link(GraficaBarraClass.clw)')
Link mode. A hand-written .cwproj that omits _ABCLinkMode_=>1 / _ABCDllMode_=>0 (or the equivalent for your own chain) links the class as an import. It compiles, links, and then faults inside Construct the first time the object is touched.

The data gridLa rejilla de datos

Every chart type reads the same structure: 48 categories across, 8 series deep. A pie has one series and calls its categories slices; a radar calls them axes; a line calls them points. Same storage.

Field by field

FieldTypeMeaning
NBarsLONGHow many categories are loaded. Everything loops 1 TO NBars; cells past it are ignored, not drawn.
BarLabel[c]STRING(32) ×48The category's label. Drawn under the axis, beside a pie slice, around a radar web, and — on a pie — used as the legend text.
BarValue[c]REAL ×48Series 1's value. This is the whole story for a single-series chart, and it is the only array a pie reads.
BarColor[c]LONG ×48Per-category colour override. COLOR:None (−1) means "use the palette". Only consulted when the chart is a pie or has one series — see colour rules.
NSeriesLONGHow many series are named. 0 and 1 both mean "one series"; SeriesCount() smooths that over.
SeriesName[s]STRING(32) ×8The legend text for a multi-series chart.
SeriesColor[s]LONG ×8Per-series colour override, COLOR:None = palette.
SeriesValue[s−1,c]REAL ×7×48Series 2…8. Note the index shift.
The one index trap: series 1 does not live in SeriesValue. Series 1 is BarValue[c]; series s for s ≥ 2 is SeriesValue[s−1,c]. That shift is why MaxSeries2 is 7 and not 8, and it exists so that v1 code — which only ever knew BarValue — keeps working untouched. Never index the arrays yourself: GetValue(s,c) and SetValue(s,c,v) hide the shift and range-check both subscripts (GraficaBarraClass.clw:111,123).

Filling it: three ways in

! 1) one series, the v1 way — label + value, colour optional
  Ventas.AddBar('Ene', 120)
  Ventas.AddBar('Feb',  95, 0B6752Eh)   ! explicit Clarion BGR long

! 2) several series — name them FIRST, then one call per category
  Ventas.AddSeries('Norte')             ! becomes series 1
  Ventas.AddSeries('Sur')               ! series 2
  Ventas.AddCat('Ene', 120, 80)         ! v1 -> Norte, v2 -> Sur
  Ventas.AddCat('Feb',  95, 60)

! 3) out of order — poke individual cells; the grid grows to fit
  Ventas.SetValue(2, 5, 61)                ! series 2, category 5
  x# = Ventas.GetValue(2, 5)
Mixing 1 and 2 is legal and sometimes what you want. AddCat with one argument is AddBar without a colour; AddBar after AddSeries loads series 1 and leaves the rest of that category at zero.

Running out of room

Nothing raises an error — the class simply stops accepting data. Guard your loop if that matters:

  • AddBar / AddCat past 48 categories: the call returns having done nothing (clw:80, clw:97).
  • AddSeries past 8: returns the current count — so the number you get back is 8 again, and two of your series will write to the same row (clw:88).
  • SetValue with a subscript outside 1…48 / 1…8: returns without storing (clw:113).
  LOOP UNTIL Access:Sales.Next()
    IF Ventas.NBars >= GraficaBarra:MaxBars THEN BREAK.   ! stop before the class does
    Ventas.AddBar(SAL:Month, SAL:Amount)
  END

Todos los tipos leen la misma estructura: 48 categorías de ancho, 8 series de fondo. Un pastel tiene una serie y llama porciones a sus categorías; un radar las llama ejes; una línea las llama puntos. El mismo almacenamiento.

Quedarse sin espacio

Nada genera un error — la clase simplemente deja de aceptar datos. Proteja su bucle si eso importa:

Life cycle & orderCiclo de vida y orden

The class has no Init and no Kill. There are, however, four ordering rules that fail silently — no error, just a chart that looks wrong.

The shape of a chart, start to finish

  ! 1. exists      — Construct has already run: 13 types' worth of defaults
  ! 2. configure   — ChartType and the look
  Ventas.ChartType = Chart:StackedCol
  Ventas.Title     = 'Ventas 2026'
  Ventas.ShowValues = 0

  ! 3. clear       — throw away whatever was in there
  Ventas.ClearAll()

  ! 4. name series — BEFORE any category
  Ventas.AddSeries('Norte')
  Ventas.AddSeries('Sur')

  ! 5. load        — one call per category
  Ventas.AddCat('Ene', 120, 80)

  ! 6. draw        — window: one call. report: aim, paint, release
  Ventas.Draw(MyWindow, ?Graph)

The four rules that fail silently

RuleDo it wrong and…
Name the series before the categories. AddSeries only sets NSeries, and AddCat stores against whatever the count is at the time — but the legend and the per-series colours are read at paint time, so what actually breaks is subtler. Values land correctly, yet a category added while NSeries was still 0 is coloured by category instead of by series, so one bar in the group has the wrong colour.
SetRange after, not before, AutoScale. SetRange sets AutoScale = 0 as its last act (clw:133). Setting AutoScale = 1 after SetRange throws the fixed scale away and the axis is derived from the data again.
ChartType before Demo(). Demo loads data suited to the current type (clw:138). Demo() then ChartType = Chart:Pie gives a pie of six monthly columns instead of the five regions it would have loaded.
On a report, SETTARGET the band — not just the report. Every chart on the report piles into whichever band happens to be printing. This is the single most common report bug; see Several charts at once.

Reusing one object

Reuse is normal — the template does it on every band of a report and on every redraw of a window. Two things to know:

  • ClearAll() throws away the data. It cannot un-draw a chart that is already on the page.
  • EraseFirst (default 1) is what actually removes the old picture: Paint wipes its own rectangle before drawing (clw:412-419). A window IMAGE gets a full BLANK; a report band gets BLANK(x,y,w,h) over the placeholder's rectangle plus a pad of bleed.
  ! the standard reuse cycle
  Ventas.ClearAll()          ! data gone
  Ventas.ChartType = Chart:Bar
  Ventas.AddBar('Norte', 20)
  Ventas.Draw(MyWindow, ?Graph)   ! EraseFirst=1 wipes the old picture for you

  ! a deliberate overlay: two charts sharing one rectangle
  Ventas.Draw(MyWindow, ?Graph)
  Ventas.EraseFirst = 0
  Costos.Draw(MyWindow, ?Graph)   ! lands ON TOP of Ventas
  Ventas.EraseFirst = 1
EraseFirst on a report erases by rectangle, not by owner. BLANK(x,y,w,h) removes everything already drawn in that rectangle of the band — including a STRING or a company logo that overlaps it. Keep other band controls outside the placeholder's rectangle, remembering that the erase is inflated by zPad (a quarter of the text cell — about 32 thousandths of an inch on a report) on every side.

La clase no tiene Init ni Kill. Sí tiene, en cambio, cuatro reglas de orden que fallan en silencio — sin error, solo un gráfico que se ve mal.

La forma de un gráfico, de principio a fin

  ! 1. existe      — Construct ya corrió: los valores por defecto están puestos
  ! 2. configure   — ChartType y la apariencia
  Ventas.ChartType = Chart:StackedCol
  Ventas.Title     = 'Ventas 2026'
  Ventas.ShowValues = 0

  ! 3. limpie      — deseche lo que hubiera dentro
  Ventas.ClearAll()

  ! 4. nombre las series — ANTES de cualquier categoría
  Ventas.AddSeries('Norte')
  Ventas.AddSeries('Sur')

  ! 5. cargue      — una llamada por categoría
  Ventas.AddCat('Ene', 120, 80)

  ! 6. dibuje      — ventana: una llamada. informe: apunte, pinte, suelte
  Ventas.Draw(MyWindow, ?Graph)

Las cuatro reglas que fallan en silencio

ReglaSi la incumple…
Nombre las series antes que las categorías. AddSeries solo fija NSeries, y AddCat guarda contra el conteo del momento — pero la leyenda y los colores por serie se leen al pintar, así que lo que se rompe es más sutil. Los valores entran bien, pero una categoría agregada mientras NSeries aún era 0 se colorea por categoría en vez de por serie, y una barra del grupo sale con el color equivocado.
SetRange después, no antes, de AutoScale. SetRange pone AutoScale = 0 como último acto (clw:133). Poner AutoScale = 1 después de SetRange descarta la escala fija y el eje vuelve a derivarse de los datos.
ChartType antes de Demo(). Demo carga datos adecuados al tipo actual (clw:138). Demo() y luego ChartType = Chart:Pie da un pastel de seis columnas mensuales en vez de las cinco regiones que habría cargado.
En un informe, SETTARGET a la banda — no solo al informe. Todos los gráficos del informe se amontonan en la banda que esté imprimiéndose. Es el error de informe más común; vea Varios gráficos a la vez.

Reutilizar un objeto

Reutilizar es lo normal — la plantilla lo hace en cada banda de un informe y en cada redibujo de una ventana. Dos cosas que saber:

  • ClearAll() desecha los datos. No puede des-dibujar un gráfico que ya está en la página.
  • EraseFirst (1 por defecto) es lo que realmente quita el dibujo anterior: Paint limpia su propio rectángulo antes de dibujar (clw:412-419). Un IMAGE de ventana recibe un BLANK completo; una banda de informe recibe BLANK(x,y,w,h) sobre el rectángulo del marcador más un margen de sangrado.
  ! el ciclo normal de reutilización
  Ventas.ClearAll()          ! datos fuera

The target's font, re-applied with the original colour at the end (clw:508), when ColorText = 1. The pen. Colour, width and style are all left wherever the last primitive put them — set your own before drawing anything else into that target.

When it draws nothing

Paint returns early, silently, in three situations. If a chart is mysteriously absent, it is almost always one of these:

  • The rectangle left for the plot is under 8 units wide or tall after the title, the legend and the padding have taken their share (clw:491). A Legend:Right can claim up to two fifths of the width.
  • The same test again after the axis furniture — scale numbers, labels, value room — has been subtracted (clw:603).
  • A pie whose computed diameter comes out under 8 units (clw:1089), or a radar whose radius does (clw:1199).
Diagnosing a blank chart: set ShowLegend = 0, Title = '' and ShowScale = 0, then call Demo(). If the chart appears, the placeholder is too small for the furniture you asked for, not broken.

Paint, step by stepPaint, paso a paso

One call traced end to end. Knowing this order explains most "why does it look like that" questions — particularly why the legend can starve the plot, and why the axis is never covered by a bar.

  1. Measure. GETPOSITION(pFeq, x, y, w, h) — the placeholder's rectangle, in the target's own units. clw:385
  2. Text metrics. zCW, zCH from TextW/TextH or the per-target defaults; then zPad and the pen scale zSc derived from zCH. clw:389-404
  3. Erase. Window mode: BLANK (the whole image) and the origin forced to 0,0. Report mode: BLANK(x−pad, y−pad, …) clamped so it can never reach outside the band. Skipped entirely when EraseFirst = 0. clw:412-419
  4. Capture the font. GETFONT(0,…) into the zF… fields, so text can be re-coloured and the font restored. clw:424
  5. Background. BackColor fills the whole rectangle, if set. clw:431
  6. Title. Drawn centred at the top — before the layout maths, because it only needs the outer rectangle. clw:436
  7. Measure the legend. Count the items (categories on a pie, series otherwise, none for a single-series non-pie), measure the longest, and reserve either a right-hand column (capped at 2/5 of the width) or one to three bottom/top rows. clw:440-472
  8. Carve out the plot rectangle. Start from the padded control rectangle, subtract the title line, subtract the legend on its side. Bail out if under 8 units either way. clw:474-491
  9. Dispatch. Pie family → PaintPie. Radar → PaintRadar, unless there are fewer than three categories, in which case the type is temporarily swapped to Chart:Line, drawn, and swapped back — your ChartType property is left exactly as you set it. Everything else → PaintCartesian. clw:493-506
  10. Legend. Drawn last, into the space step 7 reserved. clw:507
  11. Hand the font back with its original colour. clw:508

Inside PaintCartesian

  1. Work out zLo/zHi: fixed, or 0…100 for Stacked100, or derived — stacked types scale to the stack totals, everything else to the largest single value.
  2. Put zero on a gridline if the data spans zero, adjusting zDivs.
  3. Reserve margins for the scale numbers, the category labels and the value labels — different sides for horizontal charts. Bail out again if what is left is under 8 units.
  4. Fill the plot background, work out where zero is, draw the grid.
  5. Draw the data — stacks, areas, lines or bars.
  6. Draw the axis and the zero baseline over the data, so a bar never hides the line it starts from.
  7. Draw the category labels, thinning them out (every 2nd, 3rd…) until they stop colliding.

AlgorithmsAlgoritmos

The nice scale

NiceMax takes the largest value and rounds it up to the next 1, 2 or 5 times a power of ten. The guard on line 170 matters: 10 ^ INT(LOG10(v)) can land above v on an exact power of ten because of floating-point rounding, so it is stepped back down one decade.

  dmax = 71   ->  m = 10,  f = 7.1  ->  RETURN 100
  dmax = 42   ->  m = 10,  f = 4.2  ->  RETURN 50
  dmax = 0.31 ->  m = 0.1, f = 3.1  ->  RETURN 0.5

Putting zero on a gridline

When the data spans zero, a plain min…max split into 5 leaves the baseline floating between two gridlines, which reads badly. So the class picks a nice step instead and counts outward from zero in both directions (clw:568-576):

  stp   = NiceMax((zHi - zLo) / GridDivs)          ! a nice step, not a nice max
  zHi   =  stp * INT(( zHi - 0.000001) / stp + 1)  ! whole steps up
  zLo   = -stp * INT((-zLo - 0.000001) / stp + 1)  ! whole steps down
  zDivs = INT((zHi - zLo) / stp + 0.5)             ! so zDivs > GridDivs is normal

The epsilon stops a value that is already exactly on a step from being pushed a whole step further out. This is why zDivs exists separately from GridDivs: the property is what you asked for, the field is what the geometry needed.

Thinning the category labels

Labels are never drawn on top of each other. The class widens the step until they fit (clw:648-675): on a vertical chart it compares the longest label's width against the slot width and shows every n-th label, then truncates what is left to the characters that fit; on a horizontal chart it steps on the text height instead. So a 48-category column chart shows perhaps every fourth month, not 48 overlapping smudges.

100% stacks

Each value becomes 100 × ABS(v) / CatTotal(cat) — absolute, so a negative contributes its magnitude rather than eating into the stack, and the column always fills exactly 100. A category whose total is zero is skipped entirely (clw:827), leaving a gap rather than a divide-by-zero.

Smooth lines

Smooth = 1 runs a Catmull-Rom spline through the points, eight straight segments per span (clw:915-932). The end points are duplicated so the curve starts and ends at real data. It is still LINE underneath, so it stays vector on a report — at eight times the primitive count per span, which is worth knowing if you are printing many charts.

Quantising a pie

Clarion's PIE takes an array of integer slice sizes, so the class scales the values to a 100 000-unit whole (clw:1054-1072):

  • fac = 100000 / sum-of-absolute-values; each slice becomes INT(ABS(value) × fac + 0.5).
  • The tot that results — not 100 000 exactly, after rounding — is what the percentage labels divide by, so the printed percentages always add up to what is drawn.
  • All values zero is not an error: every slice becomes 1, and you get an equal-slice pie.
  • A slice under 1/100 000 of the total rounds to zero, and a zero slice is skipped by the labelling loop — it keeps its legend row but gets no label or value drawn.

The whole pie is then one PIE call, which is what keeps it vector on a report. The donut hole is an ELLIPSE drawn over the middle afterwards — which is why HoleColor exists and why it has to fall back to something opaque.

Both array statements read the whole array

POLYGON and PIE read every element of the array they are given, not just the part you filled. Two different paddings deal with that:

  • PolyDraw repeats the last corner through the tail, creating zero-length invisible edges (clw:344-349).
  • PaintPie zeroes both arrays before filling them, so unused slices have size 0 (clw:1050-1053).
If you copy this pattern into your own code: forgetting the padding does not produce an error. It produces a polygon with a spike back to whatever was left in the array from the previous chart — a bug that looks like corruption and is really an unpadded tail.

Legend sizing

Bottom and top legends measure the total width of all items, divide by the available width to get a row count, cap it at three, and reserve rows × (zCH + zPad) + zPad. The drawing loop then wraps for real and BREAKs if it runs past the bottom of the control — so with many long series names, some legend entries simply do not appear. A right-hand legend reserves the longest name plus a swatch, capped at two fifths of the width, and stacks down one column.

La escala redonda

NiceMax toma el mayor valor y lo redondea hacia arriba al siguiente 1, 2 o 5 por una potencia de diez. La protección de la línea 170 importa: 10 ^ INT(LOG10(v)) puede quedar por encima de v en una potencia exacta de diez por redondeo de coma flotante, así que se baja una década.

  dmax = 71   ->  m = 10,  f = 7,1  ->  RETURN 100
  dmax = 42   ->  m = 10,  f = 4,2  ->  RETURN 50
  dmax = 0,31 ->  m = 0,1, f = 3,1  ->  RETURN 0,5

Poner el cero en una línea de cuadrícula

Cuando los datos cruzan el cero, dividir min…max entre 5 deja la línea base flotando entre dos líneas, y se lee mal. Así que la clase elige un paso redondo y cuenta hacia afuera desde el cero en ambos sentidos (clw:568-576):

  stp   = NiceMax((zHi - zLo) / GridDivs)          ! un paso redondo, no un máximo redondo
  zHi   =  stp * INT(( zHi - 0.000001) / stp + 1)  ! pasos enteros hacia arriba
  zLo   = -stp * INT((-zLo - 0.000001) / stp + 1)  ! pasos enteros hacia abajo
  zDivs = INT((zHi - zLo) / stp + 0.5)             ! por eso zDivs > GridDivs es normal

El épsilon evita que un valor que ya cae justo en un paso se empuje un paso entero más afuera. Por esto zDivs existe aparte de GridDivs: la propiedad es lo que usted pidió, el campo es lo que la geometría necesitó.

Ralear las etiquetas de categoría

Las etiquetas nunca se dibujan unas sobre otras. La clase amplía el paso hasta que quepan (clw:648-675): en un gráfico vertical compara el ancho de la etiqueta más larga con el ancho de ranura y muestra cada n-ésima, y luego trunca lo que queda a los caracteres que caben; en uno horizontal usa la altura del texto. Así, un gráfico de 48 categorías muestra quizá cada cuarto mes, no 48 borrones superpuestos.

Pilas al 100%

Cada valor pasa a ser 100 × ABS(v) / CatTotal(cat) — absoluto, de modo que un negativo aporta su magnitud en vez de comerse la pila, y la columna siempre llena exactamente 100. Una categoría con total cero se omite por completo (clw:827), dejando un hueco en vez de una división por cero.

Líneas suaves

Smooth = 1 pasa una spline Catmull-Rom por los puntos, con ocho segmentos rectos por tramo (clw:915-932). Los puntos extremos se duplican para que la curva empiece y termine en datos reales. Por debajo sigue siendo LINE, así que sigue siendo vectorial en un informe — con ocho veces más primitivas por tramo, lo que conviene saber si imprime muchos gráficos.

Cuantizar un pastel

El PIE de Clarion recibe un arreglo de tamaños enteros de porción, así que la clase escala los valores a un total de 100 000 unidades (clw:1054-1072):

  • fac = 100000 / suma-de-valores-absolutos; cada porción pasa a ser INT(ABS(valor) × fac + 0,5).
  • El tot resultante — no exactamente 100 000 tras redondear — es entre lo que dividen las etiquetas de porcentaje, así que los porcentajes impresos siempre suman lo dibujado.
  • Todos los valores en cero no es un error: cada porción vale 1 y sale un pastel de porciones iguales.
  • Una porción menor que 1/100 000 del total se redondea a cero, y una porción cero la omite el bucle de etiquetado — conserva su fila en la leyenda pero no recibe etiqueta ni valor.

El pastel entero es entonces una sola llamada PIE, que es lo que lo mantiene vectorial en un informe. El agujero de la dona es una ELLIPSE dibujada encima al final — por eso existe HoleColor y por eso tiene que recurrir a algo opaco.

Las dos sentencias de arreglo leen todo el arreglo

POLYGON y PIE leen todos los elementos del arreglo que reciben, no solo la parte que usted llenó. Dos rellenos distintos lo resuelven:

  • PolyDraw repite la última esquina por toda la cola, creando aristas invisibles de longitud cero (clw:344-349).
  • PaintPie pone en cero ambos arreglos antes de llenarlos, así las porciones sin usar miden 0 (clw:1050-1053).
Si copia este patrón a su propio código: olvidar el relleno no produce un error. Produce un polígono con un pico que vuelve a lo que quedara en el arreglo del gráfico anterior — un fallo que parece corrupción y en realidad es una cola sin rellenar.

Dimensionar la leyenda

Las leyendas de abajo y de arriba miden el ancho total de todos los elementos, lo dividen entre el ancho disponible para obtener un número de filas, lo limitan a tres y reservan filas × (zCH + zPad) + zPad. El bucle de dibujo luego reparte de verdad y hace BREAK si se pasa del borde inferior del control — así que con muchos nombres de serie largos, algunas entradas simplemente no aparecen. Una leyenda a la derecha reserva el nombre más largo más una muestra, con tope de dos quintos del ancho, y apila en una columna.

Colour rulesReglas de color

One method decides every fill colour in the chart: ColorOf(pSeries, pCat) (clw:233). It has exactly two modes, and which one applies is decided by the data, not by a property.

WhenColour comes from
A pie family chart, or SeriesCount() = 1 Per category. BarColor[cat] if it is not COLOR:None, otherwise Palette(cat).
Two or more series Per series. SeriesColor[series] if set, otherwise Palette(series). BarColor is ignored entirely.
The consequence that surprises people: a single-series column chart draws every bar in a different palette colour, because with one series the colour goes per category. Naming the series with AddSeries does not change that — SeriesCount() is still 1. To get one colour for all the bars, set it per bar:
  LOOP UNTIL Access:Sales.Next()
    Ventas.AddBar(SAL:Month, SAL:Amount, 0B6752Eh)   ! every bar steel blue
  END

Lines, areas and radar webs behave differently on purpose: with one series they take ColorOf(1,1) for the whole shape (clw:910, 1006, 1226), because a multi-coloured polyline would be meaningless.

A chart on a reportGráfico en un informe

The report path is three lines around Paint, and the whole difficulty is in the first of them. Put the code where the band's data is current — %BeforePrint in an ABC report, or immediately before your PRINT in hand code.

Rpt   REPORT,AT(500,500,7500,10000),THOUS,FONT('Segoe UI',9)
Det     DETAIL,AT(0,0,7000,5600),USE(?Det)          ! the band NEEDS a USE()
          IMAGE,AT(250,150,6500,5000),USE(?Place)  ! placeholder: rectangle only
        END
      END
  ! …
  Ventas.ClearAll()
  Ventas.ChartType = Chart:Column
  Ventas.AddBar('Ene', 42)
  Ventas.AddBar('Feb', 58)

  SETTARGET(Rpt, ?Det)                 ! 1. aim at the BAND
  Ventas.Paint(?Place)                  ! 2. vector primitives into it
  ?Place{PROP:Hide} = 1                 ! 3. the placeholder never prints
  SETTARGET()
  PRINT(Det)
Why a placeholder at all? Paint needs a rectangle, and the report formatter is the natural place to position one. Hiding it afterwards costs nothing — the chart is already ink in the band, and the ink does not belong to the control.

What makes it stay vector

Every primitive the class uses is one the report driver records into the page metafile: BOX, LINE, POLYGON, ELLIPSE, PIE, SHOW. Nothing is rasterised, so the PDF holds shapes and text, not a bitmap — it prints at the printer's resolution and the file stays small. A pie is a single PIE record; a six-bar column chart is a handful of BOXes and a dozen strings.

Charts in a repeating band

A DETAIL that prints once per customer can carry a chart of that customer's data. Rebuild the object for each record — the band does not accumulate the previous record's drawing, and EraseFirst clears the rectangle in any case:

  LOOP UNTIL Access:Customer.Next()
    Ventas.ClearAll()
    Ventas.Title = CLIP(CUS:Name)
    ! …load this customer's months…
    SETTARGET(Rpt, ?Det)
    Ventas.Paint(?Place)
    SETTARGET()
    PRINT(Det)                          ! each row gets its own chart, auto-scaled
  END

¿Y por qué un marcador? Paint necesita un rectángulo, y el formateador de informes es el sitio natural para colocar uno. Ocultarlo después no cuesta nada — el gráfico ya es tinta en la banda, y la tinta no pertenece al control.

Qué lo mantiene vectorial

Cada primitiva que usa la clase es de las que el driver de informes graba en el metarchivo de la página: BOX, LINE, POLYGON, ELLIPSE, PIE, SHOW. Nada se rasteriza, así que el PDF guarda figuras y texto, no un mapa de bits — imprime a la resolución de la impresora y el archivo queda pequeño. Un pastel es un único registro PIE; un gráfico de seis columnas son unos cuantos BOX y una docena de cadenas.

Gráficos en una banda que se repite

Un DETAIL que se imprime una vez por cliente puede llevar un gráfico de los datos de ese cliente. Reconstruya el objeto en cada registro — la banda no acumula el dibujo del registro anterior, y EraseFirst limpia el rectángulo de todos modos:

  LOOP UNTIL Access:Customer.Next()
    Ventas.ClearAll()
    Ventas.Title = CLIP(CUS:Name)

    SETTARGET(Rpt, ?Det)
    Ventas.Paint(?Place)
    SETTARGET()

  END

La fuente del informe

La clase supone unos 9 puntos (62 × 130 milésimas). Si la fuente de la banda es mayor, escale las métricas o las etiquetas chocarán:

Several charts at onceVarios gráficos a la vez

This is where the report path bites. The rule is one line long: aim at the band that holds the placeholder, every time.

  ! WRONG — every chart lands in whichever band is printing

  Ventas.Paint(?PlaceInHeader)
  Gastos.Paint(?PlaceInDetail)
  SETTARGET()

  SETTARGET(Rpt, ?Hdr)
  Ventas.Paint(?PlaceInHeader)
  SETTARGET(Rpt, ?Det)
  Gastos.Paint(?PlaceInDetail)
  SETTARGET()

Two charts in the same band

Perfectly legal — two placeholders, two objects, one SETTARGET:

  SETTARGET(Rpt, ?Det)
  Ventas.Paint(?P1)
  Gastos.Paint(?P2)                     ! P2's erase must not overlap P1's rectangle
  SETTARGET()
Keep the rectangles apart. EraseFirst blanks a rectangle inflated by zPad on every side. Two placeholders that touch will have the second erase nibble the edge of the first chart. Leave at least a text line between them — this is exactly what experiment F4 in examples/graficaBarra/ReportClear.clw tests.

How the template finds the band

Worth knowing even if you hand-code, because it is the rule you should follow yourself: report controls come out of the template symbols in declaration order, with an indent level per control. A control's band is therefore the nearest thing declared before it at a shallower indent. That works for DETAIL, group HEADER/FOOTER, FORM and controls inside a BREAK, without the template ever needing to know the band type names. It needs the band to have a USE(?equate); without one the template emits the bare SETTARGET(report) plus a comment explaining exactly why.

Extending the classExtender la clase

No method is VIRTUAL, so the usual ABC derive-and-override does not apply: a derived PaintBars is never called by the base Paint. There are three practical routes instead.

1. Draw on top, afterwards — no class change

The best option for most additions. Paint leaves its geometry in the z… fields, so you can annotate in the same coordinate space:

  SETTARGET(Wnd, ?Chart)
  Ventas.Paint(?Chart, 1)                      ! Draw, unrolled, so the target stays ours

  ! a dashed target line at 75, labelled
  SETPENWIDTH(Ventas.zSc)
  SETPENCOLOR(0B23A2Eh)
  SETPENSTYLE(PEN:Dash)
  y# = Ventas.VY(75)
  LINE(Ventas.zPX, y#, Ventas.zPW, 0)
  SETPENSTYLE()
  Ventas.TextAt(Ventas.zPX + Ventas.zPad, y# - Ventas.zCH, 'Meta', 0B23A2Eh)
  SETTARGET()

Reusing TextAt is what keeps the annotation in the chart's font and colour handling — remember that SHOW alone would take the target's font colour, not yours.

3. Edit the class

It is your source and it is meant to be readable — the painters are short and each one owns one chart type. Two rules if you do:

  • Keep the file ANSI, CRLF. Any editor that helpfully saves UTF-8 will break the build with a message that has nothing to do with what you changed.
  • If you raise MaxBars, raise MaxPoly with it (at least 4 × MaxBars + 8), and remember one Clarion array cannot exceed 65 535 bytes — a REAL,DIM(7,n) hits that ceiling at n = 1170, and going over turns the whole CLASS into "Illegal data type" at every use site.

The natural place to add a fourteenth chart type is a new Chart: equate, a PaintWhatever method beside the others, and one more branch in Paint's dispatch at clw:493.

Behaviour that is surprising rather than wrong, and the two or three places where the code really is doing something you would not choose. Each row names the file and line and gives a workaround.

A single-series column chart draws every bar a different colour. ColorOf switches to per-category colouring whenever SeriesCount() = 1. clw:236 Pass an explicit colour to every AddBar, or add a second (zero) series.

Un GridDivs fuera de rango queda cambiado después de dibujar. PaintCartesian lo repara a 1 en la propia propiedad, no en una variable local. clw:566 Es inocuo, pero no use GridDivs como almacén de un ajuste de usuario que además quiera releer.
Las etiquetas salen demasiado grandes o pequeñas en un informe. La clase nunca fija una fuente — usa la de la banda y solo la recolorea. Fije la fuente en la banda o en el marcador desde el formateador.
Un radar con dos categorías se dibuja como línea. Una telaraña necesita tres ejes, así que Paint cambia el tipo temporalmente. Su propiedad ChartType se restaura. clw:496-500 Es por diseño — el recurso es más útil que un rectángulo vacío.
SetRange(-50, 50) en un radar arranca igual en 0. PaintRadar fuerza zLo = 0 y solo lee MaxVal. clw:1180 Desplace los datos usted mismo si necesita un piso distinto de cero. En un radar los negativos también se acotan a 0. clw:1230
Algo más de la banda desaparece cuando el gráfico se repinta. EraseFirst blanquea un rectángulo, y un rectángulo no sabe quién dibujó lo que hay dentro. clw:415-418 Saque el otro contenido del rectángulo del marcador (más un zPad de sangrado), o ponga EraseFirst = 0 y gestione el borrado usted.
Los valores sobre 999 salen con separador de miles y no hay forma de quitarlo. FmtNum usa una imagen @n, que siempre agrupa. clw:200 Escale los datos y dígalo en el título, o cambie la imagen a @n-13_ en su copia de la clase.
El texto sale en el color del destino, no en TextColor. ColorText = 0, o GETFONT no devolvió nombre de fuente — entonces TextAt recurre a SETPENCOLOR, que no colorea SHOW. clw:278-282 Deje ColorText = 1 y dele al control destino un FONT(…) explícito.
Lo que dibuja después del gráfico sale con color o grosor equivocado. Paint restaura la fuente pero no la pluma. clw:508 Fije SETPENCOLOR/SETPENWIDTH/SETPENSTYLE antes de sus propias primitivas.
No es una rareza: los gráficos no se acumulan en una banda repetida. Se probó explícitamente — examples/graficaBarra/ReportClear.clw imprime la misma banda sin pintar nada y el gráfico anterior no reaparece. Lo que sí se acumula son dos Paint en el mismo marcador antes de un solo PRINT, que es lo que vino a resolver EraseFirst.

Report extension

EmbedGenerated
%DataSectionThe object.

Both extensions are MULTI

So one procedure can carry several charts. Object names key off %ActiveTemplateInstance, which is what keeps their data, their events and their objects from colliding. Several charts in one report band work, and they follow the band down the page as it repeats, each with its own data and its own auto-scale.
