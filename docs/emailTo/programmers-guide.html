The object model

One object is yours. Everything under it is built and freed for you.

Mailer  EmailToClass          ! you declare this one

  !  and it builds, at Construct:
  !     Mailer.Net    EmailNetClass    the socket, TLS, HTTPS, DPAPI
  !     Mailer.Msg    EmailMsgClass    the message SendSimple and Compose use
  !     Mailer.OAuth  EmailOAuthClass  the sign-in
  !
  !  EmailOAuthClass only BORROWS Net and a second message object; it frees
  !  neither.  One owner, one Destruct, no double-dispose.

The split is deliberate and it is the reason emailTo needs no third-party library. EmailNetClass is the only place that touches C: sockets, the SCHANNEL handshake, WinHTTP, DPAPI, SHA-256. EmailMsgClass is pure Clarion and knows nothing about networks — it turns fields into an RFC 5322 document. EmailToClass joins them: it owns an account and knows four ways to deliver the bytes the message class produced.

Why the message class does not know about sockets

Because all four transports want the same bytes. SMTP writes them after DATA, the Gmail API base64url-encodes them into a JSON field, Graph posts them as base64 text, Mailgun uploads them as a file. Build the MIME once and every transport is a thin wrapper.

The account

Mailer.Acc is a GROUP, and it is the contract between the class and wherever you keep your settings. The template maps one table column onto each field. The fields that matter most:

FieldWhat it decides
TransportSMTP, Gmail API, Graph, or a provider API key.
ProviderWhich preset filled the rest in, and which API shape to speak.
Host / Port / SecurityThe SMTP connection.
AuthModeNothing, AUTH LOGIN, AUTH PLAIN, or an OAuth2 token.
UserName / PasswordThe credential, when it is a password.
ClientId / TenantIdThe registered application, when it is OAuth2.
RefreshTokenWhat makes the second send need no browser.
ApiKey / ApiDomainSendGrid, Mailgun, Resend, Brevo, Postmark, Mailjet.
VerifyCertLeave it at 1 unless the server is yours and self-signed.

SetProvider fills in host, port, security and sign-in for fourteen providers, so an account is usually three lines: the provider, the address and the credential.

Composing a message

Recipients come in one at a time with AddTo / AddCc / AddBcc, or all at once with AddList, which takes the way people actually type them — separated by ; or ,, with any amount of stray space.

Bcc behaves properly. A Bcc address is added to the envelope as an extra RCPT TO and is deliberately not written into the headers, so the other recipients never see it.

Bodies are set with SetText and SetHtml, appended with AddText and AddHtml. Attachments come from disk with Attach, from memory with AttachData, and an image the HTML refers to goes in with AttachInline:

  Mailer.Msg.ClearAll()
  Mailer.Msg.AddTo(Cus:Email)
  Mailer.Msg.SetSubject('Your statement')
  Mailer.Msg.SetHtml('<p><img src="cid:logo" width="180"></p>' & |
                     '<p>Your statement is attached.</p>')
  Mailer.Msg.AttachInline('C:\art\logo.png', 'logo')
  Mailer.Msg.Attach('C:\stmt\' & CLIP(Cus:Id) & '.pdf')
  Mailer.Send(Mailer.Msg)

Accents, and why they survive

A Clarion STRING holds Windows-1252 bytes. Sent as-is, Factura Número arrives as mojibake, because nothing told the reader what those bytes meant.

emailTo transcodes the subject, the display names, the bodies and the attachment file names to UTF-8 and labels them. Headers are wrapped in RFC 2047 encoded words split on character boundaries — never through the middle of a character — and bodies go out quoted-printable. A plain English note is still sent as readable 7bit text, because the encoder only reaches for quoted-printable when the content, or a 998-byte line, actually needs it.

Mailer.Msg.CharSet = ETChs:Ansi   ! send the raw bytes labelled windows-1252 instead

Choosing a transport

TransportWhen it is the right one
ETTrn:SmtpAlmost always. Any server, any provider that still allows a password or supports XOAUTH2.
ETTrn:GmailApiA Google account where you would rather not enable SMTP at all. Needs OAuth2.
ETTrn:GraphApiMicrosoft 365 tenants that have SMTP AUTH disabled — increasingly, all of them.
ETTrn:ApiKeyA deployed application that must just send, on a network where port 587 may be blocked.

Switching is one field. The message, the attachments and the error handling are identical:

Mailer.Acc.Transport = ETTrn:GraphApi

OAuth2, end to end

Google and Microsoft no longer accept an ordinary password from a desktop program. The flow emailTo runs is the authorisation-code flow with PKCE, which is the one they document for native applications:

  1. Invent a random verifier and hash it with SHA-256 into a challenge.
  2. Open a listener on http://127.0.0.1:<a free port>/ — before the browser, so no redirect can be missed.
  3. Open the user’s own browser at the provider’s consent screen, carrying the challenge and a random state.
  4. Catch the redirect, check the state matches, and swap the returned code plus the verifier for an access token and a refresh token.
  Mailer.Acc.Provider  = ETPrv:Office365
  Mailer.Acc.Transport = ETTrn:GraphApi
  Mailer.Acc.ClientId  = '11111111-2222-3333-4444-555555555555'
  Mailer.Acc.TenantId  = 'common'
  Mailer.Acc.UserName  = 'you@company.com'

  IF Mailer.Authorize()                     ! browser opens; user consents
    Mailer.SaveAccount()                    ! stores the refresh token, sealed
  ELSE
    MESSAGE(CLIP(Mailer.LastErrorText))
  END

A desktop client ID is not a secret

That is what PKCE is for. Microsoft public clients must send no client secret at all, and emailTo only sends one when the account actually has one. Nothing confidential is compiled into your .EXE.

Register at console.cloud.google.com → Credentials → OAuth client ID → Desktop app, or portal.azure.com → App registrations → Public client with redirect http://localhost.

After the first consent nobody sees a browser again. EnsureToken runs before every send: if the access token is still good it does nothing, if it has expired it spends the refresh token silently, and only when there is no refresh token left does it ask the user to sign in.

Google only issues a refresh token when asked properly

It needs access_type=offline and prompt=consent, and without them the second send fails with no obvious cause. emailTo sends both. Microsoft instead rotates the refresh token on every use, so the new one has to be stored each time — which is why Refresh writes it back.

One class, nine providers

EmailToClass answers one question: send this. EmailApiClass answers all the others — who is blocked, what happened last month, which contacts and campaigns exist — and it answers them the same way whoever you signed up with.

It owns nothing of its own. Init(Mailer) borrows the account and the HTTPS layer, so the key the Setup window sealed is the key these calls use, and there is no second copy of a credential anywhere in the program.

  PROGRAM

  INCLUDE('EmailApiClass.INC'),ONCE

  MAP
  END

Mailer   EmailToClass
MailApi  EmailApiClass
i        LONG

  CODE
  Mailer.Init(PATH() & '\mail.ini')
  Mailer.LoadAccount()                        ! the key you stored in Setup
  MailApi.Init(Mailer)                        ! borrows that account - no second copy

  IF MailApi.GetSuppressions(ETSup:All) < 0
    MESSAGE(CLIP(MailApi.LastErrorText))
  ELSE
    LOOP i = 1 TO RECORDS(MailApi.SuppQ)
      GET(MailApi.SuppQ, i)
      !  MailApi.SuppQ.Address   who
      !  MailApi.SuppQ.KindName  bounce / blocked / spam report / unsubscribed
      !  MailApi.SuppQ.Reason    what the receiving server actually said
      !  MailApi.SuppQ.WhenDate  when
    END
  END

Underneath it is three layers, and only the middle one knows anything about a provider:

LayerWhat it isKnows about providers?
BuildMap()The matrix. One row per operation per provider.Yes — and it is the only thing that does
Fetch / PerformThe engine: expand the URL, sign it, follow the paging, parse, map.No
GetXxx / AddXxxThe public methods. Set the arguments, call the engine.No

The matrix

Adding a provider is adding rows, not writing branches. A row says: for THIS provider and THIS operation, use this verb and this address, the list is at this path in the reply, and these JSON members fill these columns.

  SELF.Row(ETPrv:SendGrid, ETOp:Suppressions, ETSup:Bounce, 'GET', |
           '{scheme}{host}/v3/suppression/bounces?limit={limit}&offset={offset}', '', |
           'Address=email;Reason=reason;Id=status;When=#created')

  SELF.Row(ETPrv:Brevo, ETOp:Suppressions, ETSup:All, 'GET', |
           '{scheme}{host}/v3/smtp/blockedContacts?limit={limit}&offset={offset}', |
           'contacts', |
           'Address=email;Reason=reason.message;KindText=reason.code;When=@blockedAt')

The pieces of a row:

PartWhat it means
{scheme}{host}The provider’s address, honouring ApiRegion (eu) and ApiBase (anything you name, scheme included).
{limit} {offset} {page}Filled in by the paging loop, over and over, until the provider runs out.
{email} {id} {text} {subject} {html}Your data. Percent-encoded in a URL, JSON-escaped in a body — the engine can tell which it is building.
{ymdfrom} {isofrom} {epochfrom} {rfcfrom}The same date range in the four spellings the nine providers want.
the item pathWhere the array of rows sits: blank means the reply IS the array, * means the reply is ONE item. A path that turns out not to be there falls back to the first array in the document.
the mapColumn=source pairs. A source may be a path (reason.message), may offer alternates (recipient.email|email), may be a literal (!spam report), and may carry a date converter: # unix, @ ISO-8601, % RFC-2822, $ a plain day.

ETSup:All on a list row means something specific

Providers split their block lists two ways. SendGrid keeps five separate ones and each row is registered under its own kind. Brevo, Postmark and SparkPost keep ONE list and label each entry, so their row is registered under ETSup:All — and the engine then reads each row’s real kind out of the provider’s own wording (hardBounce, SpamNotification, policy_suppression) through SuppKindOf(). Ask either sort for one kind and you get that kind.

The normalised answers

Every read fills a queue that looks the same whoever answered. That is the whole bargain: the differences are absorbed in the matrix, and your code never learns them.

QueueWhat is in a row
SuppQAddress, Kind, KindName, Reason, Code, WhenDate, WhenTime, Id, Sender, Raw
StatQWhenDate, Requests, Delivered, Opens, UniqueOpens, Clicks, UniqueClicks, HardBounces, SoftBounces, Blocks, SpamReports, Unsubscribed, Invalid
EventQWhenDate, WhenTime, Address, EventName, Reason, Subject, MessageId, Link
ContactQ ListQ CampaignQId, Address, Name, Blocked, Unsubscribed … / Id, Name, Members … / Id, Name, Subject, Status …
TemplateQ SenderQ DomainQ HookQThe same treatment for the rest of the account

SuppQ.Raw keeps the provider’s own object for the row, so anything the queue has no column for is still there when you need to log the one entry that looks wrong.

A LIST cannot be pointed at these

FROM(MailApi.SuppQ) compiles and then faults on the first paint: these are queue REFERENCES, and the control binds to the reference variable itself. Copy the rows into a real local QUEUE for display — which is where you want to format the dates anyway. Manage() does exactly that, and the demo shows it.

Paging, three ways

A block list is not a page long, and the nine providers disagree about how to walk it. The engine handles all three without the caller knowing:

StyleWhoWhat the engine does
limit and offsetSendGrid, Brevo, Mailjet, PostmarkAsks again with the offset advanced, and stops when a page comes back shorter than the page size.
page numberSparkPost, MailerSendThe same, counted in pages instead of rows.
a cursorMailgunFollows the address the reply carries in paging.next, and stops when a page comes back empty.
a continuation tokenAmazon SESHands the token back as a parameter named after the path it arrived at, so the matrix row says NextToken and the engine needs to know nothing about Amazon.

PageSize sets how many to ask for at a time and MaxRows is the guard — 5,000 by default, 0 for no limit. A hundred thousand suppressed addresses is a real thing at a large sender, and reading them all into memory by accident should be a decision rather than a surprise.

One list refusing does not lose the others

Asking SendGrid for everything means five requests. If one of them fails — an endpoint an account’s plan does not open, a permission the key was not given — the other four still answer, and the failure is in LastErrorText. A partial answer is a great deal more use than none.

Adding a provider

BuildMap is VIRTUAL, so a provider the shipped matrix does not know needs no change to any file emailTo ships:

MyApiClass  CLASS(EmailApiClass)
BuildMap      PROCEDURE(),DERIVED
            END

MyApiClass.BuildMap PROCEDURE()
  CODE
  PARENT.BuildMap()                           ! keep the eight that are already there
  SELF.Row(ETPrv:Custom, ETOp:Suppressions, ETSup:All, 'GET', |
           '{scheme}{host}/api/blocked?page={page}', 'rows', |
           'Address=addr;Reason=why;When=@stamp')
  SELF.Row(ETPrv:Custom, ETOp:SuppDelete, ETSup:All, 'DELETE', |
           '{scheme}{host}/api/blocked/{email}')

Set Acc.Provider to ETPrv:Custom and Acc.ApiBase to the host, and every method above works against it — including Manage(), which reads Supports() to decide which tabs to offer.

For a single call that deserves no row at all, RawCall() signs the request with this account and hands you back the status; the reply is in Net.Body(), and Json is right there to parse it.

Where the settings live

LoadAccount and SaveAccount are VIRTUAL. Out of the box they read and write an INI beside the .EXE, which is enough for a demo and for a single-user program. Nominate a table on the global extension and the template overrides them with code shaped like this:

Mailer.LoadAccount PROCEDURE(<STRING pName>)
  CODE
  IF NOT OMITTED(pName) AND CLIP(pName)
    SELF.Acc.Name = CLIP(pName)
  END
  Access:MailAcct.Open()
  Access:MailAcct.UseFile()
  CLEAR(MAI:Record)
  MAI:Name = SELF.Acc.Name
  GET(MailAcct, MAI:ByName)
  IF ERRORCODE()
    Access:MailAcct.Close()
    RETURN 0                                ! nothing stored yet - keep the defaults
  END
  SELF.Acc.Host     = CLIP(MAI:Host)
  SELF.Acc.Password = SELF.Unseal(MAI:Password)
  ! ... one line per mapped column ...
  Access:MailAcct.Close()
  RETURN 1

Both methods open and close the file around their own work through the ABC FileManager, whose Open and Close are reference-counted — so it is safe whether or not the table is already open elsewhere in the program.

Secrets at rest

Four fields are never stored in the clear: the password, the client secret, the refresh token and the API key. Each goes through Seal() — DPAPI encrypts it for the current Windows user, then base64 makes the result safe for a text column.

Set:Password = Mailer.Seal(Loc:Typed)      ! 'dpapi:AQAAANCMnd8BFdERjHoAwE...'

A row copied to another machine, or read by another Windows user, decrypts to nothing. Size those columns generously: the stored value is three to four times longer than what was typed.

A password typed straight into the column still works

Unseal() recognises a value that is not one of its own and hands it back unchanged, which makes seeding a test row easy. A machine with no DPAPI gets a plain: prefix instead, so nobody mistakes it for encrypted.

Errors, and the log

Every public method answers 1 for worked and 0 for failed, and leaves the reason in LastErrorText as a sentence you can show a user. LastServerReply holds the last thing the server actually said, which is usually more specific than anything emailTo could invent.

IF NOT Mailer.Send(Mailer.Msg) THEN Mailer.ShowError().

With Trace on, the whole conversation is kept in Mailer.Net.TraceQ and shown on the Log tab of the setup window. Credentials are masked before they reach it, so a customer can send you the log of a failed send without sending you their password.

A LIST cannot be pointed at TraceQ directly

TraceQ is a queue reference, and FROM(Mailer.Net.TraceQ) binds the control to the reference variable rather than to the queue. The window then faults on its first paint. Copy into a real local QUEUE for display — the demo and the setup window both do.

Making it do something else

The methods worth overriding are marked VIRTUAL: Txt for a third language, LoadAccount / SaveAccount for your own store, and the four Send* methods for logging, throttling or a retry policy.

MyMailer  CLASS(EmailToClass)
Txt         PROCEDURE(LONG pId),STRING,DERIVED
SendSmtp    PROCEDURE(EmailMsgClass pMsg),BYTE,PROC,DERIVED
          END

MyMailer.Txt PROCEDURE(LONG pId)
  CODE
  IF GlobalLanguage = LNG:Portuguese
    CASE pId
    OF ETTxt:Send  ; RETURN 'Enviar'
    OF ETTxt:Sent  ; RETURN 'A mensagem foi enviada.'
    END
  END
  RETURN PARENT.Txt(pId)                    ! English and Spanish still work

MyMailer.SendSmtp PROCEDURE(EmailMsgClass pMsg)
Ok  BYTE
  CODE
  Ok = PARENT.SendSmtp(pMsg)
  Log:Sent = Ok; Log:Reason = SELF.LastErrorText; ADD(SendLog)
  RETURN Ok

Clarion notes

These are not emailTo behaviours — they belong to Clarion. Each one cost real time to find while this was being built, and each is the kind of thing that is invisible until it bites.

A method named Clear breaks CLEAR() everywhere

A class member whose label matches a Clarion intrinsic redefines that intrinsic for every module that includes the file. The compiler says Redefining system intrinsic: CLEAR at the include, and then CLEAR(SomeVariable) in code that has nothing to do with your class stops compiling.

!  In the CLASS declaration:
ClearAll             PROCEDURE       ! correct
!  Clear              PROCEDURE      ! WRONG - redefines the CLEAR intrinsic

!  With a method called Clear, this line, in code that has nothing to do
!  with e-mail, stops compiling:
  CLEAR(GlobalRequest)               ! error: No matching prototype available

This is why the buffer and message classes have ClearAll. RESET, ADD, LEN and FREE are the other names to keep away from.

A STRING bound to a variable needs a picture

Written with a literal instead, the control survives on its own — and then faults inside OPEN(Window) as soon as the same window also holds a LIST. Nothing is drawn, so there is no clue on screen about which control is at fault.

!  WRONG - a literal, on a control bound to a variable.  Survives on its own,
!  faults inside OPEN(Window) as soon as the window also holds a LIST.
         STRING(''),AT(10,130,280,10),USE(LocStatus),FONT(,8)

!  RIGHT - a picture wide enough for the variable
         STRING(@s128),AT(10,130,280,10),USE(LocStatus),FONT(,8)

The way to find one like this is to open variants of the window with one control removed at a time: the variant that opens names the culprit. Here two removals fixed it — the LIST, or the bound STRINGs — which is what said it was the combination rather than either one.

No Clarion picture is wider than @s255

ENTRY(@s512) is a compile error — Invalid picture token. In a FORMAT string it is worse, because FORMAT is just text to the compiler and nothing is reported at all. Keep list formats at @s255 and give the entry a wider variable if you need one.

A MEMBER module with no MAP loses the built-ins

A module-level MAP is what folds in BUILTINS.CLW. Without one — even an empty one — CLIP, CHOOSE and the rest come back as Unknown function label, dozens of times, which reads like a corrupt include rather than a missing four lines.

  MEMBER

  INCLUDE('EmailToClass.INC'),ONCE

  MAP
  END

A method returning STRING cannot free its own buffer

The copy happens at the RETURN, so anything disposed first is gone before the caller sees it. The buffer has to outlive the return, which means it belongs to the object — and each encoder needs its own, because they nest.

!  A method that returns a STRING cannot free the buffer it built the answer
!  in: the copy happens at the RETURN.  So the buffer belongs to the object.
EmailMsgClass.Base64 PROCEDURE(STRING pRaw)
  CODE
  SELF.EncBuf.ClearAll()
  ! ... fill SELF.EncBuf ...
  RETURN SELF.EncBuf.Value()

!  And each encoder gets its OWN buffer, because they nest: the inner result
!  is still live while the outer call reads it.
  pOut.Add(SELF.QuotedPrintable(SELF.Utf8(pBody.Value())))

Clarion source must be CRLF

An LF-only include mis-parses as Illegal data type: <CLASS> at the declaration, with nothing flagged inside the include. Note that sed -i strips the CR and writes LF, so a one-line edit is enough to break a file that compiled a minute earlier.

SCHANNEL asks for a client certificate you do not have

Google’s SMTP, and Office 365, request an optional client certificate. With no certificate in the credential, InitializeSecurityContext returns SEC_I_INCOMPLETE_CREDENTIALS (0x00090320) rather than continuing, and the handshake stops. The fix is to re-issue the same token — loop again without reading more data — and the handshake completes anonymously. Without it every connection to Gmail fails.

The lone full stop

In SMTP, a line consisting of a single . ends the message. A body line that legitimately starts with a full stop must therefore be sent with two, and the receiving server removes one. Get this wrong and a message is silently truncated at the first such line — which is exactly the kind of thing that never shows up in testing and then happens to a customer.
