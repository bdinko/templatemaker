Only the first one is required

Add emailTo - Global and both objects exist everywhere. The other six are conveniences that call them — anything they do, you can do from a hand-written embed with the same one-line calls.

Global Properties → Extensions → Insert. Six tabs.

Account

The defaults the object starts with. If a settings table is nominated, whatever it holds overrides these at start-up and the setup window writes changes back; with no table these are the settings and the setup window saves to an INI.

A password on this tab is in your executable

Anyone with the .EXE has it. For anything you would not publish, leave it blank and let the setup window store it — that path puts it through DPAPI for the Windows user.

Sign-in

The OAuth2 application and the API keys. Client ID is the desktop client you registered with Google or Microsoft; it is not a secret. Client secret stays blank for Microsoft public clients. Tenant is Microsoft only — common accepts both a personal account and a work one, which is what an application shipped to unknown customers needs. API domain is Mailgun only; for Mailjet the public key goes in User name and the private key in API key.

emailTo - Sync

A SEPARATE application extension — emailTo - Sync provider data into your tables, added once alongside the global one. The management window asks the provider live and keeps nothing; this is the other option: nominate tables, and the same answers are also written into your own data — so you can put an ABC browse on the blocked list, join it to your customer table, or report on last month’s opens without going near the network.

There is a ready-made dictionary &mdash; import the .dctx

emailToTables.dctx ships beside the template and holds all six tables plus the account table. In the Dictionary Editor: File → Import, and pick the DCTX / XML entry.

Not emailToTables.txd. A .txd is Report Writer’s format and the Dictionary Editor refuses it outright — "This TXD file is a Report Writer only format". It ships only for ClarionCL /di, which builds a whole dictionary from text rather than importing into an existing one.

TableOne row isFilled from
MailBlockedAn address the provider refuses, with the reason, the SMTP code and whenGetSuppressions()
MailStatOne dayGetStats()
MailEventOne thing that happened to one messageGetEvents()
MailContactA contactGetContacts()
MailListA contact list and its sizeGetLists()
MailCampaignA campaign and its statusGetCampaigns()

Every table but the account carries Provider and SyncedOn, so one dictionary serves an application that switches provider or keeps two accounts.

PromptWhat it does
Sync object name / API object nameWhat to call the object it declares, and the API object the global extension declared for it to read through.
Keep the provider’s data in tablesTurns the tables on. Off, nothing here generates.
Stamp each row with the provider and the dateFills Provider and SyncedOn if the table has them. Leave it on unless one table serves exactly one account.
Table / Key (six times)The table, and the key that identifies one row — that key is what makes the sync an update rather than a duplicate.
How many days backFor statistics and activity, which are asked for over a date range rather than in full.

Columns are matched by NAME, not mapped one by one

A table imported from the shipped dictionary needs no mapping at all: the template walks the columns of whatever table you nominate and fills the ones whose names it recognises. A column called anything else is left alone — so a flag of your own, a note, or a link to your customer row all survive every sync.

That also means you can point it at a table you already have: name the columns as the dictionary does and it fills them.

What it generates is a small object of its own with one method, Run.

Why this is a separate extension, and not another tab

An application stores the set of prompts it was built with. A prompt added to an extension the app already carries is simply not there, and generating stops with Unknown Variable on a symbol the developer never typed — AppGen does not fill in the DEFAULT from the command line.

An app that does not add THIS extension never names these symbols, so every existing application keeps generating exactly as it did. That is worth one extra Insert.

The Provider API tab, added to the global extension in v1.03, does not have that protection: upgrading an app older than v1.03 means opening that extension's property sheet once, so the IDE writes the new prompts back. From a build script that never opens the IDE, delete the extension and insert it again.

MailApi          CLASS(EmailApiClass)              ! the object, writing into your tables
SyncTables         PROCEDURE(BYTE pSilent=0),LONG,PROC,DERIVED
                 END

!  ... and, generated beside it:

MailApi.SyncTables PROCEDURE(BYTE pSilent)
  CODE
  DO ETySyncBlocked                               ! one routine per table you nominated
  DO ETySyncStats
  ...

ETySyncBlocked ROUTINE
  ETyN = SELF.GetSuppressions(ETSup:All)
  IF ETyN < 0 THEN ETyBad = 1; EXIT.
  Access:MailBlocked.Open()
  Access:MailBlocked.UseFile()
  LOOP ETyi = 1 TO RECORDS(SELF.SuppQ)
    GET(SELF.SuppQ, ETyi)
    CLEAR(MailBlocked:Record)
    DO ETyMapBlocked
    GET(MailBlocked, MBL:ByAddress)               ! already there?
    IF ERRORCODE()
      CLEAR(MailBlocked:Record); DO ETyMapBlocked
      ADD(MailBlocked)
    ELSE
      DO ETyMapBlocked
      PUT(MailBlocked)                            ! update, never duplicate
    END
  END
  Access:MailBlocked.Close()

ETyMapBlocked ROUTINE
  MBL:Address   = SELF.SuppQ.Address
  MBL:Kind      = SELF.SuppQ.Kind
  MBL:Reason    = SELF.SuppQ.Reason
  MBL:BlockedOn = SELF.SuppQ.WhenDate
  MBL:Provider  = SELF.Mailer.Acc.Provider
  MBL:SyncedOn  = TODAY()

Each row is looked up by its key before it is written, so running the sync twice changes nothing: a row already there is updated, a new one is added, and the count comes back the same. That is what makes it safe on a button anybody can press twice, or on a timer.

The sync button

emailTo - Sync mail data into your tables is a control template: drag it onto a window and it drops a wired button that calls the generated method.

PromptWhat it does
Sync object nameThe object the emailTo - Sync extension declared.
Quietly — no message when it finishesOff, it reports how many rows came down and how many were new. On for a button that runs unattended.
Put the row count inA variable of yours, for a status line.
Reset the browse afterwardsCalls ResetFromFile() on the browse you name, so a browse of the synced table shows the new rows without the user closing the window.

For a menu item or a batch process instead, the emailTo - Ask the provider code template has Sync it all into my tables as one of its operations.

Table, and Table columns

Nominate a table and the template generates LoadAccount and SaveAccount against it. Pick the key it finds an account by, name the account to load at start-up, then map a column onto each field.

Each column prompt is a picker: the … button beside it lists the columns of the table you nominated, so the mapping is chosen rather than typed.

PromptNotes
Settings tableBlank means use an INI beside the .EXE.
Key to find the account byUsed for the GET in both directions.
Account to load at start-upBlank loads the first record instead.
Create the row if it is missingOn, the setup window can ADD the account.
Account nameThe only required column.
Every other columnOptional. Unmapped keeps whatever the Account tab set.

Four columns need to be wide

Password, client secret, refresh token and API key are stored sealed, so they are three to four times longer than what was typed. Make them at least 400 characters, and the refresh token 2000. EmailTables.txt ships a structure ready to paste into a dictionary.

Multi-DLL

Add the extension to every application in the suite and leave the box alone. The app that owns the data compiles the classes in and exports them; the others import them. The classes are tagged !ABCIncludeFile(EMAILTO), and registering that category hands the whole job to the shipped ABC machinery — it writes the project defines and walks the registry to build the .EXP.

#pragma define(_emailToDllMode_=>0)
#pragma define(_emailToLinkMode_=>1)

That is why nothing in the template lists a mangled symbol: add a method to a class and the export list follows on the next generate. emailc.c is compiled only into the application that owns the classes, because the PRAGMA lives in EmailNetClass.clw.

What the global extension writes

With no settings table, into the PROGRAM module:

!  %AfterGlobalIncludes
INCLUDE('EmailToClass.INC'),ONCE

!  %GlobalData
Mailer             EmailToClass                            ! the mail object
emailToLanguage        BYTE(1)                             ! 1 = English, 2 = Espanol

!  %ProgramSetup, PRIORITY(8000)
    Mailer.Init()
    Mailer.Language = emailToLanguage
    Mailer.Trace = 1
    Mailer.SetProvider(1)                     ! host, port, security and auth
    Mailer.Acc.Transport = 1
    Mailer.Acc.Host      = 'smtp.gmail.com'
    Mailer.Acc.Port      = 587
    Mailer.Acc.Security  = 1
    Mailer.Acc.AuthMode  = 1
    Mailer.Acc.UserName  = 'sales@acme.com'
    Mailer.Acc.FromAddr  = 'sales@acme.com'
    Mailer.LoadAccount()

With one, the object is derived instead, and the binding is written out in full at %ProgramProcedures:

!  %GlobalData, when a settings table is nominated
Mailer             CLASS(EmailToClass)
LoadAccount              PROCEDURE(<STRING pName>),BYTE,PROC,DERIVED
SaveAccount              PROCEDURE(),BYTE,PROC,DERIVED
                       END

!  %ProgramProcedures - the whole binding, written from your column mapping
Mailer.LoadAccount PROCEDURE(<STRING pName>)
  CODE
  ...

Why deriving still works across a suite

The derived instance is declared only in the application that owns it. The others import it as the base type and still reach the derived methods, because both are VIRTUAL and dispatch through the object’s own VMT.

emailTo - Provider API

A SEPARATE application extension, added once alongside the global one. The same key that sends the mail can also answer for the account, so this needs nothing except a name.

It was a tab on the global extension in v1.03

That was a mistake, and it broke every application built before v1.03: an app stores the set of prompts it was built with, and AppGen does not backfill one added later — generation stopped with Unknown Variable %ETgApi, on a symbol nobody typed.

As an extension of its own it cannot do that: an app that does not add it never names its symbols. If you had the tab switched on in v1.03, insert this extension and put the object name back — what the old tab stored is simply ignored.

PromptWhat it does
Object nameWhat to call it. MailApi unless you have a reason — the control and code templates default to that name too.
Mail object nameThe object emailTo - Global declared. This one borrows its account and its HTTPS layer, so there is no second copy of a credential anywhere in the program.
Rows per requestThe page size. The class keeps asking until the provider runs out, so this is not a limit, only how much comes back at a time.
Stop after this many rowsThe guard: 5,000 by default, 0 for no limit.
Second keyPostmark alone needs two tokens: the SERVER token sends and reads bounces, the ACCOUNT token opens senders and domains. Blank for everybody else. All three of these can come from your settings table instead — name a column ApiKey2, ApiRegion or ApiBase and the global extension fills it, by name, with no prompt to set.
Regioneu for a Mailgun or SparkPost account created in Europe. Those are separate services with their own hostnames and their own data — asked at the default endpoint, a European account looks empty rather than wrong.
Base addressReplaces the provider’s host, and its scheme if you give one. For a relay of your own, or for pointing a test build at a stand-in. Blank in production.

Nominate a settings table on the Table tab and three more columns become available for these on the second columns tab: second key (sealed), region and base address.

The mail account button

emailTo - Mail account button is a control template: drag it onto any window and it drops a wired button that opens the management window.

PromptWhat it does
API object nameThe object the global extension declared.
Open onWhich tab: Account, Blocked addresses, Statistics, Activity, Contacts, Lists, Campaigns, Templates, Senders and domains, or Webhooks. If this provider cannot answer that one, the window opens on the first tab it CAN answer rather than showing an empty list.
Hide the button if the provider has no APIAn account sending over plain SMTP — a company Exchange server, Gmail with an app password — has no management API at all. Ticked, the button disappears for those accounts instead of opening a window with every tab greyed out. It is a run-time test, so one build serves both.

Drop it more than once and each instance gets its own tab: one button for the blocked list, another for campaigns. The template writes the event handler against whichever field equate AppGen gave that instance.

Asking from an embed

emailTo - Ask the provider is the code template. Drop it in any embed — a button, a menu item, the end of a process — and pick the operation:

PromptWhat it does
Do thisLoad the blocked addresses, unblock one, unblock every one, block an address, is this address blocked, load the statistics, the activity, the contacts, the lists, the campaigns, send a campaign, export the blocked list to CSV, or open the management window.
Which listEverything, bounces, blocked, spam reports, unsubscribed or invalid. A provider that keeps one list for all of them answers the same rows whichever you pick, labelled with what they really are.
ValueThe address, campaign id or file name the operation works on — typed, or taken from a variable at run time.
Put the result inFor a load, the NUMBER of rows (or -1 if the provider said no). For everything else, 1 means it worked.
Show the errorPops the provider’s own words. Either way they are in LastErrorText, and the address called is in LastUrl.

What it writes is short, because the class is where the work is:

  Loc:Rows = MailApi.GetSuppressions(0)
  IF MailApi.LastError
    MailApi.ShowError()
  END

The rows land in the object’s queues, which are the same shape whoever the provider is — SuppQ, StatQ, EventQ and the rest. Loop them yourself, or call Manage() and let the shipped window do it.

emailTo - E-mail button

Drag it onto any window; drop it more than once if you want to. AppGen uniques the field equate (?EmailBtn, ?EmailBtn:2…) and the template attaches the handler to whichever one this instance got.

Which button holds the sender's address? Neither

An account belongs to the application, not to a button. The server, the from address, the user name, the password and the OAuth2 client are set once, on emailTo - Global’s Account tab. A button only says what to do — so you can put two on one window, one to send and one to open the setup window, and neither of them carries a credential.

The button’s own Account tab has no prompts for exactly that reason. It is there to point at the place that does.

Which of the two a given instance is shows in the AppGen list without opening it, because the description names the action:

emailTo - E-mail button   E-mail button - opens the COMPOSE window
emailTo - E-mail button   E-mail button - opens ACCOUNT SETUP

General

PromptWhat it does
Disable this buttonGenerates nothing for this instance. The button stays on the window, inert.
Mail object nameMust match the global extension. Mailer by default.
ActionOpen the compose window, send straight away with no window, or open the account setup window.
Tell the user it workedGreyed unless the action is send straight away — the only action that reads it.
Show the error if it failedSame. Calls ShowError; off, the reason is still in LastErrorText.

All three actions start life labelled "E-mail..."

The action is chosen after the control is dropped, so the template cannot vary the caption for you. Rename the button in the window designer — two buttons that both read E-mail... confuse the user of the finished program as much as they confuse you in AppGen.

Account

No prompts. It names the one place the account is configured — Application → Global Properties → Extensions → emailTo - Global → Account — and explains that a setup-window button is how an end user overrides it: into your settings table if you mapped one, otherwise into an INI beside the .EXE.

Message

Who it goes to and what it says. What this tab means depends on the action, which is why the General tab spells the three cases out:

ActionWhat the Message tab does
Open the compose windowPre-fills the window. The user can change any of it before sending.
Send straight awayIs the message. Nothing is shown; anything left blank is omitted.
Open the account setup windowNothing — the whole tab greys out, because no message is involved.
PromptWhat it does
To / Cc / Subject / BodyLiterals for a button that always sends the same thing.
…or take it from a variableA field picker. Overrides the literal beside it.
Body is HTMLCalls SetHtml instead of SetText.
AttachmentA literal path, or a variable holding one.

Here are all three actions, as generated:

!  %ControlEventHandling, on this button's Accepted
    OF ?EmailBtn
      ThisWindow.Update()
        Mailer.Compose('bob@example.com', 'Hello from Clarion', 'It works.', '')
    OF ?EmailBtn:2
      ThisWindow.Update()
          Mailer.Msg.ClearAll()
          Mailer.Msg.AddList('ops@example.com', ETAddr:To)
          Mailer.Msg.AddList('audit@example.com', ETAddr:Cc)
          Mailer.Msg.SetSubject('Nightly run finished')
          Mailer.Msg.SetHtml('<p>Fixed <b>HTML</b> body.</p>')
        IF Mailer.Send(Mailer.Msg)
          MESSAGE(Mailer.Txt(ETTxt:Sent), Mailer.Txt(ETTxt:Compose), ICON:Asterisk)
        ELSE
          Mailer.ShowError()
        END
    OF ?EmailBtn:3
      ThisWindow.Update()
        Mailer.Setup()

The three code templates

Send an e-mail here is the one that gets used most. Its prompts mirror the button’s Message tab, plus a place to put the result:

PromptWhat it does
To / Cc / BccLiterals, or a variable for To.
Subject / BodyLiterals, or variables. Body can be HTML.
AttachmentA literal path, or a variable — this is how a report gets mailed.
Put the result inA field that receives 1 for sent, 0 for not.
Tell the user it worked / Show the errorBoth optional; the reason is always in LastErrorText.

Mailing a report

Write the PDF, then drop Send an e-mail here immediately after it and point the attachment prompt at the variable holding the file name. That is the whole recipe — there is no separate report template because there does not need to be one.

Open the compose window here pre-fills and opens the write-and-send window. Open the mail account setup window here opens the account window — put it on a Setup menu and your users can configure their own mail without you.

All three carry the same reminder the button does: the sender address, the server and the password are not among their prompts, because they belong to the global extension.
