Acceso

La aplicación OAuth2 y las claves API. El ID de cliente es el cliente de escritorio que registró con Google o Microsoft; no es un secreto. El dominio API es sólo de Mailgun; para Mailjet la clave pública va en Usuario y la privada en Clave API.

emailTo - Sync

Una extensión de aplicación APARTE — emailTo - Sync provider data into your tables, que se agrega una vez junto a la global. La ventana de gestión pregunta al proveedor en vivo y no guarda nada; ésta es la otra opción: nombre unas tablas y las mismas respuestas se escriben además en sus propios datos — así puede poner un browse ABC sobre la lista de bloqueados, unirla con su tabla de clientes, o hacer un informe de las aperturas del mes pasado sin acercarse a la red.

Hay un diccionario ya hecho &mdash; importe el .dctx

emailToTables.dctx viene junto a la plantilla y contiene las seis tablas más la tabla de la cuenta. En el editor de diccionario: File → Import, y elija la entrada DCTX / XML.

No emailToTables.txd. Un .txd es el formato de Report Writer y el editor de diccionario lo rechaza sin más — "This TXD file is a Report Writer only format". Se entrega sólo para ClarionCL /di, que construye un diccionario entero a partir de texto en vez de importar dentro de uno que ya existe.

TablaUna fila esSe llena desde

Todas las tablas menos la de la cuenta llevan Provider y SyncedOn, de modo que un diccionario sirve para una aplicación que cambia de proveedor o que lleva dos cuentas.

Las columnas se emparejan por NOMBRE, no una por una

Una tabla importada del diccionario que se entrega no necesita ningún mapeo: la plantilla recorre las columnas de la tabla que usted nombre y llena aquellas cuyo nombre reconoce. Una columna que se llame de otra manera se deja en paz — así una bandera suya, una nota, o un enlace a su fila de cliente sobreviven a cada sincronización.

Eso también significa que puede apuntarla a una tabla que ya tiene: nombre las columnas como lo hace el diccionario y las llena.

Lo que genera es un objeto pequeño propio, con un solo método, Run.

Por qué es una extensión aparte y no otra pestaña

Una aplicación guarda el conjunto de campos con el que fue construida. Un campo agregado a una extensión que la aplicación ya lleva simplemente no está, y la generación se detiene con Unknown Variable sobre un símbolo que el programador nunca escribió — AppGen no rellena el DEFAULT desde la línea de comandos.

Una aplicación que no agregue ESTA extensión nunca nombra esos símbolos, así que todas las aplicaciones existentes siguen generando igual que antes. Eso vale un Insert de más.

La pestaña API del proveedor, agregada a la extensión global en la v1.03, no tiene esa protección: actualizar una aplicación anterior a la v1.03 exige abrir una vez la hoja de propiedades de esa extensión, para que el IDE vuelva a escribir los campos nuevos. Desde un script que nunca abre el IDE, borre la extensión y vuelva a insertarla.

MailApi          CLASS(EmailApiClass)              ! the object, writing into your tables
SyncTables         PROCEDURE(BYTE pSilent=0),LONG,PROC,DERIVED
                 END

!  ... and, generated beside it:

MailApi.SyncTables PROCEDURE(BYTE pSilent)
  CODE
  DO ETySyncBlocked                               ! one routine per table you nominated
  DO ETySyncStats
  ...

ETySyncBlocked ROUTINE
  ETyN = SELF.GetSuppressions(ETSup:All)
  IF ETyN < 0 THEN ETyBad = 1; EXIT.
  Access:MailBlocked.Open()
  Access:MailBlocked.UseFile()
  LOOP ETyi = 1 TO RECORDS(SELF.SuppQ)
    GET(SELF.SuppQ, ETyi)
    CLEAR(MailBlocked:Record)
    DO ETyMapBlocked
    GET(MailBlocked, MBL:ByAddress)               ! already there?
    IF ERRORCODE()
      CLEAR(MailBlocked:Record); DO ETyMapBlocked
      ADD(MailBlocked)
    ELSE
      DO ETyMapBlocked
      PUT(MailBlocked)                            ! update, never duplicate
    END
  END
  Access:MailBlocked.Close()

ETyMapBlocked ROUTINE
  MBL:Address   = SELF.SuppQ.Address
  MBL:Kind      = SELF.SuppQ.Kind
  MBL:Reason    = SELF.SuppQ.Reason
  MBL:BlockedOn = SELF.SuppQ.WhenDate
  MBL:Provider  = SELF.Mailer.Acc.Provider
  MBL:SyncedOn  = TODAY()

Cada fila se busca por su clave antes de escribirla, así que correr la sincronización dos veces no cambia nada: una fila que ya está se actualiza, una nueva se agrega, y la cuenta vuelve igual. Eso es lo que la hace segura en un botón que cualquiera puede pulsar dos veces, o en un temporizador.

Tabla, y Columnas de la tabla

Señale una tabla y la plantilla genera LoadAccount y SaveAccount contra ella. Elija la clave con la que encuentra una cuenta, indique cuál cargar al arrancar, y luego asigne una columna a cada campo.

Cada campo de columna es un selector: el botón … de al lado lista las columnas de la tabla que señaló, así que el mapeo se elige en vez de escribirse.

CampoNotas
Tabla de configuraciónVacío significa usar un INI junto al .EXE.
Clave para encontrar la cuentaSe usa para el GET en los dos sentidos.
Cuenta a cargar al arrancarVacío carga en su lugar el primer registro.
Crear la fila si no existeEncendido, la ventana de configuración puede hacer ADD de la cuenta.

Todas las demás columnasOpcionales. Sin asignar, se conserva lo que puso la pestaña Cuenta.

Cuatro columnas tienen que ser anchas

Contraseña, secreto de cliente, token de refresco y clave API se guardan sellados, así que son tres o cuatro veces más largos que lo que se escribió. Póngalos de al menos 400 caracteres, y el token de refresco de 2000. EmailTables.txt trae una estructura lista para pegar en un diccionario.

Multi-DLL

Agregue la extensión a todas las aplicaciones de la suite y no toque la casilla. La aplicación dueña de los datos compila las clases y las exporta; las demás las importan. Las clases llevan la etiqueta !ABCIncludeFile(EMAILTO), y registrar esa categoría le entrega todo el trabajo a la maquinaria de ABC: ella escribe las definiciones del proyecto y recorre el registro para armar el .EXP.

#pragma define(_emailToDllMode_=>0)
#pragma define(_emailToLinkMode_=>1)

Por eso en la plantilla no hay ningún símbolo con nombre decorado: agregue un método a una clase y la lista de exportación lo sigue en la siguiente generación. emailc.c se compila sólo dentro de la aplicación dueña de las clases, porque el PRAGMA vive en EmailNetClass.clw.

Qué escribe la extensión global

Sin tabla de configuración, dentro del módulo PROGRAM:

!  %AfterGlobalIncludes
INCLUDE('EmailToClass.INC'),ONCE

!  %GlobalData
Mailer             EmailToClass                            ! the mail object
emailToLanguage        BYTE(1)                             ! 1 = English, 2 = Espanol

!  %ProgramSetup, PRIORITY(8000)
    Mailer.Init()
    Mailer.Language = emailToLanguage
    Mailer.Trace = 1
    Mailer.SetProvider(1)                     ! host, port, security and auth
    Mailer.Acc.Transport = 1
    Mailer.Acc.Host      = 'smtp.gmail.com'
    Mailer.Acc.Port      = 587
    Mailer.Acc.Security  = 1
    Mailer.Acc.AuthMode  = 1
    Mailer.Acc.UserName  = 'sales@acme.com'
    Mailer.Acc.FromAddr  = 'sales@acme.com'
    Mailer.LoadAccount()

Con una, el objeto se declara derivado, y el enlace se escribe completo en %ProgramProcedures:

Por qué derivar sigue funcionando en una suite

La instancia derivada se declara sólo en la aplicación que la posee. Las demás la importan como el tipo base y de todos modos alcanzan los métodos derivados, porque los dos son VIRTUAL y se despachan por la VMT del propio objeto.

emailTo - Provider API

En la v1.03 era una pestaña de la extensión global

Fue un error, y rompía toda aplicación construida antes de la v1.03: una aplicación guarda el conjunto de campos con el que fue construida, y AppGen no rellena uno agregado después — la generación se detenía con Unknown Variable %ETgApi, sobre un símbolo que nadie escribió.

Como extensión propia no puede hacer eso: una aplicación que no la agrega nunca nombra sus símbolos. Si tenía la pestaña encendida en la v1.03, inserte esta extensión y vuelva a poner el nombre del objeto — lo que guardaba la pestaña vieja simplemente se ignora.

La pestaña que declara el segundo objeto. La misma clave que envía el correo puede además contestar por la cuenta, así que aquí no hace falta más que un nombre.

CampoQué hace

Object nameCómo se llama. MailApi, salvo que tenga un motivo: las plantillas de control y de código también usan ese nombre por omisión.

Regioneu para una cuenta de Mailgun o SparkPost creada en Europa. Son servicios separados, con sus propios nombres de host y sus propios datos — preguntada en el endpoint por omisión, una cuenta europea se ve vacía en vez de equivocada.

Si nombra una tabla de configuración en la pestaña Tabla, aparecen tres columnas más para éstos en la segunda pestaña de columnas: segunda clave (sellada), región y dirección base.

El botón de cuenta de correo

emailTo - Mail account button es una plantilla de control: arrástrela a cualquier ventana y coloca un botón ya cableado que abre la ventana de gestión.

CampoQué hace
API object nameEl objeto que declaró la extensión global.
Open onPor qué pestaña: Cuenta, Bloqueados, Estadísticas, Actividad, Contactos, Listas, Campañas, Plantillas, Remitentes y dominios, o Webhooks. Si este proveedor no puede contestar ésa, la ventana abre por la primera que SÍ puede, en vez de enseñar una lista vacía.

Colóquela más de una vez y cada instancia se queda con su propia pestaña: un botón para la lista de bloqueados y otro para las campañas. La plantilla escribe el manejador contra el equate de campo que AppGen le haya dado a esa instancia.

Preguntar desde un embed

emailTo - Ask the provider es la plantilla de código. Póngala en cualquier embed — un botón, una opción de menú, el final de un proceso — y elija la operación:

CampoQué hace
Do thisCargar las direcciones bloqueadas, desbloquear una, desbloquearlas todas, bloquear una dirección, saber si una dirección está bloqueada, cargar las estadísticas, la actividad, los contactos, las listas o las campañas, enviar una campaña, exportar la lista de bloqueados a CSV, o abrir la ventana de gestión.
Which listTodo, rebotes, bloqueados, quejas de spam, bajas o no válidas. Un proveedor que guarda una sola lista para todas devuelve las mismas filas elija lo que elija, etiquetadas con lo que son de verdad.
ValueLa dirección, el id de campaña o el nombre de archivo sobre el que opera — escrito, o tomado de una variable en tiempo de ejecución.
Put the result inPara una carga, el NÚMERO de filas (o -1 si el proveedor dijo que no). Para lo demás, 1 significa que funcionó.
Show the errorMuestra las palabras del propio proveedor. En cualquier caso quedan en LastErrorText, y la dirección a la que llamó en LastUrl.

Lo que escribe es corto, porque el trabajo está en la clase:

  Loc:Rows = MailApi.GetSuppressions(0)
  IF MailApi.LastError
    MailApi.ShowError()
  END

Las filas caen en las colas del objeto, que tienen la misma forma sea quien sea el proveedor — SuppQ, StatQ, EventQ y las demás. Recórralas usted, o llame a Manage() y deje que lo haga la ventana que ya viene hecha.

emailTo - Botón de correo

Arrástrelo a cualquier ventana; póngalo más de una vez si quiere. AppGen hace único el equate del campo (?EmailBtn, ?EmailBtn:2…) y la plantilla engancha el manejador al que le haya tocado a esta instancia.

¿Cuál botón lleva la dirección del remitente? Ninguno

Una cuenta pertenece a la aplicación, no a un botón. El servidor, la dirección de remitente, el usuario, la contraseña y el cliente OAuth2 se configuran una sola vez, en la pestaña Cuenta de emailTo - Global. Un botón sólo dice qué hacer, así que puede poner dos en una misma ventana, uno para enviar y otro para abrir la configuración, y ninguno de los dos lleva una credencial.

La pestaña Cuenta del botón no tiene campos precisamente por eso. Está ahí para señalar el lugar que sí los tiene.

Cuál de los dos es cada instancia se ve en la lista de AppGen sin abrirla, porque la descripción nombra la acción:

emailTo - E-mail button   E-mail button - opens the COMPOSE window
emailTo - E-mail button   E-mail button - opens ACCOUNT SETUP

Las tres acciones nacen rotuladas "E-mail..."

La acción se elige después de soltar el control, así que la plantilla no puede variar el texto por usted. Renombre el botón en el diseñador de ventanas: dos botones que dicen los dos E-mail... confunden al usuario del programa terminado tanto como lo confunden a usted en AppGen.

Cuenta

Sin campos. Nombra el único lugar donde se configura la cuenta — Aplicación → Propiedades globales → Extensiones → emailTo - Global → Cuenta — y explica que un botón de configuración es como el usuario final la sobreescribe: a su tabla de ajustes si mapeó una, y si no, a un INI junto al .EXE.

Mandar un reporte por correo

Escriba el PDF y luego ponga Enviar un correo aquí justo después, apuntando el campo del adjunto a la variable que tiene el nombre del archivo. Esa es toda la receta: no hay una plantilla aparte para reportes porque no hace falta.

Abrir la ventana de redacción aquí prellena y abre la ventana de escribir y enviar. Abrir la ventana de configuración aquí abre la ventana de la cuenta: póngala en un menú de configuración y sus usuarios pueden configurar su propio correo sin usted.

Las tres llevan el mismo recordatorio que el botón: la dirección de remitente, el servidor y la contraseña no están entre sus campos, porque pertenecen a la extensión global.
