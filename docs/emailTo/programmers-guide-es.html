El modelo de objetos

Un objeto es suyo. Todo lo que cuelga de él se construye y se libera solo.

Mailer  EmailToClass          ! you declare this one

  !  and it builds, at Construct:
  !     Mailer.Net    EmailNetClass    the socket, TLS, HTTPS, DPAPI
  !     Mailer.Msg    EmailMsgClass    the message SendSimple and Compose use
  !     Mailer.OAuth  EmailOAuthClass  the sign-in
  !
  !  EmailOAuthClass only BORROWS Net and a second message object; it frees
  !  neither.  One owner, one Destruct, no double-dispose.

La separación es deliberada, y es la razón por la que emailTo no necesita ninguna librería de terceros. EmailNetClass es lo único que toca C: sockets, el handshake de SCHANNEL, WinHTTP, DPAPI, SHA-256. EmailMsgClass es Clarion puro y no sabe nada de redes: convierte campos en un documento RFC 5322. EmailToClass une los dos: tiene una cuenta y sabe cuatro maneras de entregar los bytes que produjo la clase del mensaje.

Por qué la clase del mensaje no sabe de sockets

Porque los cuatro transportes quieren los mismos bytes. SMTP los escribe después de DATA, la API de Gmail los codifica en base64url dentro de un campo JSON, Graph los publica como texto en base64, y Mailgun los sube como archivo. Se construye el MIME una vez y cada transporte es una envoltura delgada.

La cuenta

Mailer.Acc es un GROUP, y es el contrato entre la clase y donde sea que usted guarde su configuración. La plantilla asigna una columna de tabla a cada campo. Los que más importan:

CampoQué decide
TransportSMTP, API de Gmail, Graph, o una clave API del proveedor.
ProviderQué preajuste llenó lo demás, y qué forma de API hablar.
Host / Port / SecurityLa conexión SMTP.
AuthModeNada, AUTH LOGIN, AUTH PLAIN, o un token OAuth2.
UserName / PasswordLa credencial, cuando es una contraseña.
ClientId / TenantIdLa aplicación registrada, cuando es OAuth2.
RefreshTokenLo que hace que el segundo envío no necesite navegador.
ApiKey / ApiDomainSendGrid, Mailgun, Resend, Brevo, Postmark, Mailjet.
VerifyCertDéjelo en 1 salvo que el servidor sea suyo y con certificado propio.

SetProvider llena servidor, puerto, seguridad y autenticación para catorce proveedores, así que una cuenta suelen ser tres líneas: el proveedor, la dirección y la credencial.

Armar un mensaje

Los destinatarios entran de uno en uno con AddTo / AddCc / AddBcc, o todos juntos con AddList, que acepta la forma en que la gente los escribe de verdad: separados por ; o ,, con los espacios de más que sean.

La copia oculta se comporta como debe. Una dirección en Bcc se agrega al sobre como un RCPT TO más y deliberadamente no se escribe en los encabezados, así que los demás destinatarios nunca la ven.

Los cuerpos se fijan con SetText y SetHtml, y se amplían con AddText y AddHtml. Los adjuntos vienen del disco con Attach, de memoria con AttachData, y una imagen a la que se refiere el HTML entra con AttachInline:

  Mailer.Msg.ClearAll()
  Mailer.Msg.AddTo(Cus:Email)
  Mailer.Msg.SetSubject('Your statement')
  Mailer.Msg.SetHtml('<p><img src="cid:logo" width="180"></p>' & |
                     '<p>Your statement is attached.</p>')
  Mailer.Msg.AttachInline('C:\art\logo.png', 'logo')
  Mailer.Msg.Attach('C:\stmt\' & CLIP(Cus:Id) & '.pdf')
  Mailer.Send(Mailer.Msg)

Los acentos, y por qué sobreviven

Un STRING de Clarion guarda bytes Windows-1252. Enviado tal cual, Factura Número llega hecho un desastre, porque nada le dijo al lector qué significaban esos bytes.

emailTo convierte el asunto, los nombres visibles, los cuerpos y los nombres de archivo adjuntos a UTF-8 y los etiqueta. Los encabezados se envuelven en palabras codificadas RFC 2047 partidas en los límites de carácter — nunca a la mitad de uno — y los cuerpos salen en quoted-printable. Una nota sencilla en inglés sigue saliendo como texto 7bit legible, porque el codificador sólo recurre a quoted-printable cuando el contenido, o una línea de 998 bytes, de verdad lo necesita.

Mailer.Msg.CharSet = ETChs:Ansi   ! mandar los bytes crudos como windows-1252

Elegir un transporte

TransporteCuándo es el correcto
ETTrn:SmtpCasi siempre. Cualquier servidor, cualquier proveedor que todavía acepte una contraseña o que soporte XOAUTH2.
ETTrn:GmailApiUna cuenta de Google donde prefiere no habilitar SMTP. Requiere OAuth2.
ETTrn:GraphApiInquilinos de Microsoft 365 con SMTP AUTH deshabilitado, que cada vez son más.
ETTrn:ApiKeyUna aplicación desplegada que sólo tiene que enviar, en una red donde el puerto 587 puede estar bloqueado.

Cambiar es un campo. El mensaje, los adjuntos y el manejo de errores son idénticos:

Mailer.Acc.Transport = ETTrn:GraphApi

OAuth2, de principio a fin

Google y Microsoft ya no aceptan una contraseña común desde un programa de escritorio. El flujo que corre emailTo es el de código de autorización con PKCE, que es el que ellos documentan para aplicaciones nativas:

  1. Inventar un verificador al azar y sacarle SHA-256 para obtener un desafío.
  2. Abrir un escucha en http://127.0.0.1:<un puerto libre>/, antes que el navegador, para que no se pierda ninguna redirección.
  3. Abrir el navegador del propio usuario en la pantalla de consentimiento del proveedor, llevando el desafío y un state al azar.
  4. Atrapar la redirección, comprobar que el state coincide, y cambiar el código devuelto más el verificador por un token de acceso y un token de refresco.
  Mailer.Acc.Provider  = ETPrv:Office365
  Mailer.Acc.Transport = ETTrn:GraphApi
  Mailer.Acc.ClientId  = '11111111-2222-3333-4444-555555555555'
  Mailer.Acc.TenantId  = 'common'
  Mailer.Acc.UserName  = 'you@company.com'

  IF Mailer.Authorize()                     ! browser opens; user consents
    Mailer.SaveAccount()                    ! stores the refresh token, sealed
  ELSE
    MESSAGE(CLIP(Mailer.LastErrorText))
  END

Un ID de cliente de escritorio no es un secreto

Para eso es PKCE. Los clientes públicos de Microsoft no deben mandar ningún secreto de cliente, y emailTo sólo manda uno cuando la cuenta realmente lo tiene. En su .EXE no queda compilado nada confidencial.

Regístrelo en console.cloud.google.com → Credenciales → ID de cliente de OAuth → Aplicación de escritorio, o en portal.azure.com → Registros de aplicaciones → Cliente público con redirección http://localhost.

Después del primer consentimiento nadie vuelve a ver un navegador. EnsureToken corre antes de cada envío: si el token de acceso todavía sirve no hace nada, si venció gasta el token de refresco en silencio, y sólo cuando ya no queda token de refresco le pide al usuario que inicie sesión.

Google sólo emite token de refresco si se le pide bien

Necesita access_type=offline y prompt=consent, y sin ellos el segundo envío falla sin causa aparente. emailTo manda los dos. Microsoft en cambio rota el token de refresco en cada uso, así que hay que guardar el nuevo cada vez, que es por lo que Refresh lo vuelve a escribir.

Una clase, nueve proveedores

EmailToClass responde a una pregunta: envía esto. EmailApiClass responde a todas las demás — quién está bloqueado, qué pasó el mes pasado, qué contactos y campañas hay — y las responde igual sea cual sea el proveedor con el que usted se dio de alta.

No tiene nada propio. Init(Mailer) toma prestadas la cuenta y la capa HTTPS, así que la clave que selló la ventana de configuración es la que usan estas llamadas, y no hay una segunda copia de ninguna credencial en ninguna parte del programa.

  PROGRAM

  INCLUDE('EmailApiClass.INC'),ONCE

  MAP
  END

Mailer   EmailToClass
MailApi  EmailApiClass
i        LONG

  CODE
  Mailer.Init(PATH() & '\mail.ini')
  Mailer.LoadAccount()                        ! the key you stored in Setup
  MailApi.Init(Mailer)                        ! borrows that account - no second copy

  IF MailApi.GetSuppressions(ETSup:All) < 0
    MESSAGE(CLIP(MailApi.LastErrorText))
  ELSE
    LOOP i = 1 TO RECORDS(MailApi.SuppQ)
      GET(MailApi.SuppQ, i)
      !  MailApi.SuppQ.Address   who
      !  MailApi.SuppQ.KindName  bounce / blocked / spam report / unsubscribed
      !  MailApi.SuppQ.Reason    what the receiving server actually said
      !  MailApi.SuppQ.WhenDate  when
    END
  END

Por dentro son tres capas, y sólo la del medio sabe algo de un proveedor:

La matriz

Añadir un proveedor es añadir filas, no escribir ramas. Una fila dice: para ESTE proveedor y ESTA operación, use este verbo y esta dirección, la lista está en esta ruta de la respuesta, y estos miembros JSON llenan estas columnas.

  SELF.Row(ETPrv:SendGrid, ETOp:Suppressions, ETSup:Bounce, 'GET', |
           '{{scheme}{{host}/v3/suppression/bounces?limit={{limit}&offset={{offset}', '', |
           'Address=email;Reason=reason;Id=status;When=#created')

  SELF.Row(ETPrv:Brevo, ETOp:Suppressions, ETSup:All, 'GET', |
           '{{scheme}{{host}/v3/smtp/blockedContacts?limit={{limit}&offset={{offset}', |
           'contacts', |
           'Address=email;Reason=reason.message;KindText=reason.code;When=@blockedAt')

Las piezas de una fila:

PiezaQué significa
{scheme}{host}La dirección del proveedor, respetando ApiRegion (eu) y ApiBase (lo que usted diga, esquema incluido).
{limit} {offset} {page}Los llena el bucle de paginación, una y otra vez, hasta que el proveedor se queda sin filas.
{email} {id} {text} {subject} {html}Sus datos. Codificados con % en una URL y escapados como JSON en un cuerpo — el motor sabe cuál de los dos está armando.
{ymdfrom} {isofrom} {epochfrom} {rfcfrom}El mismo rango de fechas en las cuatro escrituras que quieren los ocho.
la ruta del elementoDónde está el arreglo de filas: vacío significa que la respuesta ES el arreglo, * que la respuesta es UN elemento. Una ruta que resulte no estar ahí cae en el primer arreglo del documento.
el mapaPares Columna=origen. Un origen puede ser una ruta (reason.message), ofrecer alternativas (recipient.email|email), ser un literal (!spam report) y llevar un convertidor de fecha: # unix, @ ISO-8601, % RFC-2822, $ un día suelto.

ETSup:All en una fila de lista significa algo concreto

Los proveedores parten sus listas de bloqueo de dos maneras. SendGrid guarda cinco separadas y cada fila se registra con su propio tipo. Brevo, Postmark y SparkPost guardan UNA sola y etiquetan cada entrada, así que su fila se registra con ETSup:All — y entonces el motor deduce el tipo real de cada fila de las palabras del propio proveedor (hardBounce, SpamNotification, policy_suppression) con SuppKindOf(). Pídale un tipo a cualquiera de los dos y recibe ese tipo.

Las respuestas normalizadas

Cada lectura llena una cola que se ve igual conteste quien conteste. Ése es el trato completo: las diferencias se absorben en la matriz, y su código no llega a aprenderlas nunca.

Amazon es el que no acepta una clave en una cabecera

SES firma la petición — verbo, ruta, consulta, cabeceras y un hash del cuerpo — con una clave derivada del secreto, la fecha, la región y el servicio. Por eso EmailNetClass ganó SignAws, Hmac256 y los demás: están junto al SHA-256 sobre el que se construyen, y tanto enviar como preguntar usan los mismos. Cada pieza está comprobada contra un vector que publican el RFC 4231 o Amazon.

Ponga el access key id de AWS en Second key y el secreto en la clave de API. User name y Password quedan libres para las credenciales SMTP, muy distintas, que SES también emite, de modo que una cuenta puede hacer las dos cosas. La región forma parte de la firma, así que tiene que ser la correcta — en blanco significa us-east-1.

ColaQué hay en una fila
SuppQAddress, Kind, KindName, Reason, Code, WhenDate, WhenTime, Id, Sender, Raw
StatQWhenDate, Requests, Delivered, Opens, UniqueOpens, Clicks, UniqueClicks, HardBounces, SoftBounces, Blocks, SpamReports, Unsubscribed, Invalid
EventQWhenDate, WhenTime, Address, EventName, Reason, Subject, MessageId, Link
ContactQ ListQ CampaignQId, Address, Name, Blocked, Unsubscribed … / Id, Name, Members … / Id, Name, Subject, Status …
TemplateQ SenderQ DomainQ HookQLo mismo para el resto de la cuenta

SuppQ.Raw conserva el objeto original del proveedor para esa fila, así que lo que la cola no tiene columna para guardar sigue estando ahí cuando haga falta registrar la entrada que se ve rara.

Un LIST no puede apuntar a estas colas

FROM(MailApi.SuppQ) compila y luego truena al primer dibujado: son REFERENCIAS a cola, y el control se liga a la variable de referencia. Copie las filas a un QUEUE local de verdad para mostrarlas — que es donde va a querer formatear las fechas de todos modos. Manage() hace exactamente eso, y la demostración lo enseña.

Paginación, de tres maneras

Una lista de bloqueados no cabe en una página, y los nueve proveedores no se ponen de acuerdo en cómo recorrerla. El motor se ocupa de las tres sin que quien llama se entere:

EstiloQuiénQué hace el motor
límite y desplazamientoSendGrid, Brevo, Mailjet, PostmarkVuelve a pedir con el desplazamiento avanzado, y para cuando una página vuelve más corta que el tamaño de página.
número de páginaSparkPost, MailerSendLo mismo, contado en páginas en vez de en filas.
un cursorMailgunSigue la dirección que la respuesta trae en paging.next, y para cuando una página vuelve vacía.
un token de continuaciónAmazon SESDevuelve el token como un parámetro que se llama igual que la ruta por la que llegó, así que la fila de la matriz dice NextToken y el motor no necesita saber nada de Amazon.

PageSize dice cuántas pedir de una vez y MaxRows es la guarda — 5000 por omisión, 0 para no poner límite. Cien mil direcciones suprimidas es algo real en un remitente grande, y leerlas todas en memoria debería ser una decisión, no una sorpresa.

Que una lista falle no pierde las demás

Pedirle todo a SendGrid son cinco peticiones. Si una falla — un endpoint que el plan de esa cuenta no abre, un permiso que la clave no tiene — las otras cuatro siguen contestando, y el fallo queda en LastErrorText. Una respuesta parcial sirve muchísimo más que ninguna.

Añadir un proveedor

BuildMap es VIRTUAL, así que un proveedor que la matriz de fábrica no conoce no obliga a tocar ningún archivo de los que emailTo entrega:

MyApiClass  CLASS(EmailApiClass)
BuildMap      PROCEDURE(),DERIVED
            END

MyApiClass.BuildMap PROCEDURE()
  CODE
  PARENT.BuildMap()                           ! keep the eight that are already there
  SELF.Row(ETPrv:Custom, ETOp:Suppressions, ETSup:All, 'GET', |
           '{{scheme}{{host}/api/blocked?page={{page}', 'rows', |
           'Address=addr;Reason=why;When=@stamp')
  SELF.Row(ETPrv:Custom, ETOp:SuppDelete, ETSup:All, 'DELETE', |
           '{{scheme}{{host}/api/blocked/{{email}')

Ponga Acc.Provider en ETPrv:Custom y Acc.ApiBase en el host, y todos los métodos de arriba funcionan contra él — incluida Manage(), que lee Supports() para decidir qué pestañas ofrecer.

Para una llamada suelta que no merece una fila, RawCall() firma la petición con esta cuenta y le devuelve el estado; la respuesta está en Net.Body(), y Json está ahí mismo para analizarla.

Dónde vive la configuración

LoadAccount y SaveAccount son VIRTUAL. De fábrica leen y escriben un INI junto al .EXE, que alcanza para una demostración y para un programa de un solo usuario. Señale una tabla en la extensión global y la plantilla los reemplaza con código de esta forma:

Mailer.LoadAccount PROCEDURE(<STRING pName>)
  CODE
  IF NOT OMITTED(pName) AND CLIP(pName)
    SELF.Acc.Name = CLIP(pName)
  END
  Access:MailAcct.Open()
  Access:MailAcct.UseFile()
  CLEAR(MAI:Record)
  MAI:Name = SELF.Acc.Name
  GET(MailAcct, MAI:ByName)
  IF ERRORCODE()
    Access:MailAcct.Close()
    RETURN 0                                ! nothing stored yet - keep the defaults
  END
  SELF.Acc.Host     = CLIP(MAI:Host)
  SELF.Acc.Password = SELF.Unseal(MAI:Password)
  ! ... one line per mapped column ...
  Access:MailAcct.Close()
  RETURN 1

Los dos métodos abren y cierran el archivo alrededor de su propio trabajo con el FileManager de ABC, cuyos Open y Close llevan cuenta de referencias, así que da igual si la tabla ya estaba abierta en otra parte del programa.

Varias cuentas, un solo programa

Una cuenta tiene nombre, y el almacén guarda una configuración por nombre. Nada se comparte entre ellas — proveedor, clave, región, dominio, forma de autenticarse, todo pertenece a la cuenta — así que un programa puede quedar configurado para SendGrid y Brevo a la vez, y cambiar de una a otra en una línea:

Mailer.Acc.Name     = 'brevo'                 ! a name nothing has used yet
Mailer.Acc.Provider = ETPrv:Brevo
Mailer.Acc.ApiKey   = 'xkeysib-...'
Mailer.SaveAccount()                          ! creates a SECOND account

IF Mailer.ListAccounts() > 1                  ! AccountQ: .Name .Provider .ProviderText .FromAddr
   Mailer.LoadAccount('brevo')                ! switch - the other one is untouched
   MailApi.Manage(2)                          ! it borrows whatever is loaded
END

Con un INI la cuenta predeterminada es la sección [emailTo] y una con nombre es [emailTo_brevo]. Con una tabla es una fila por nombre, buscada por la clave de la columna del nombre. A un INI no se le puede preguntar qué secciones tiene, así que las que llevan nombre mantienen un índice en la sección base que SaveAccount actualiza; una tabla simplemente se recorre. Por eso ListAccounts y DeleteAccount son VIRTUAL como los otros dos: sólo el código generado sabe leer su tabla.

MétodoQué hace
LoadAccount(name)Cambia a esa cuenta. Sin argumento, la predeterminada sin nombre.
SaveAccount()Escribe bajo Acc.Name. Un nombre que nadie usó todavía crea una segunda cuenta.
ListAccounts()Llena AccountQ con cada cuenta del almacén — nombre, proveedor, texto del proveedor y dirección — y contesta cuántas hay. La fila 1 es la predeterminada sin nombre.
DeleteAccount(name)Olvida una. La predeterminada sin nombre no se puede borrar.
RememberAccount(name)Con cuál abrir la próxima vez.
PreferredAccount(fallback)Ese nombre, o el de reserva si nunca se fijó, o si la cuenta que nombra ya fue borrada.

La ventana de configuración hace todo esto sin código

Encima de las pestañas lleva Cuenta:, una lista desplegable con todo lo guardado, con Cargar y Quitar; y Guardar como: debajo, donde un nombre nuevo crea una segunda cuenta. Cargar o guardar una la recuerda, y la línea de arranque generada es LoadAccount(PreferredAccount('default')), así que un programa cambiado a un segundo proveedor vuelve a abrir con él.

Los secretos guardados

Cuatro campos nunca se guardan en claro: la contraseña, el secreto de cliente, el token de refresco y la clave API. Cada uno pasa por Seal(): DPAPI lo cifra para el usuario actual de Windows, y luego base64 deja el resultado apto para una columna de texto.

Set:Password = Mailer.Seal(Loc:Typed)      ! 'dpapi:AQAAANCMnd8BFdERjHoAwE...'

Una fila copiada a otra máquina, o leída por otro usuario de Windows, se descifra en nada. Dele tamaño de sobra a esas columnas: el valor guardado es tres o cuatro veces más largo que lo que se escribió.

Una contraseña escrita a mano en la columna igual funciona

Unseal() reconoce un valor que no es de los suyos y lo devuelve tal cual, lo que hace fácil sembrar una fila de prueba. Una máquina sin DPAPI recibe un prefijo plain:, para que nadie lo confunda con algo cifrado.

Los errores, y el registro

Todo método público contesta 1 si funcionó y 0 si no, y deja el motivo en LastErrorText como una frase que se le puede mostrar al usuario. LastServerReply guarda lo último que dijo el servidor, que casi siempre es más específico que cualquier cosa que emailTo pudiera inventar.

IF NOT Mailer.Send(Mailer.Msg) THEN Mailer.ShowError().

Con Trace encendido, toda la conversación queda en Mailer.Net.TraceQ y se muestra en la pestaña Registro de la ventana de configuración. Las credenciales se ocultan antes de llegar ahí, así que un cliente puede mandarle el registro de un envío fallido sin mandarle su contraseña.

Un LIST no se puede apuntar directo a TraceQ

TraceQ es una referencia a cola, y FROM(Mailer.Net.TraceQ) liga el control a la variable de referencia en vez de a la cola. La ventana entonces truena en su primer dibujado. Copie a una QUEUE local de verdad para mostrarla, como hacen la demostración y la ventana de configuración.

Hacer que haga otra cosa

Los métodos que vale la pena sobrescribir están marcados VIRTUAL: Txt para un tercer idioma, LoadAccount / SaveAccount para su propio almacén, y los cuatro métodos Send* para bitácora, limitación de ritmo o una política de reintentos.

MyMailer  CLASS(EmailToClass)
Txt         PROCEDURE(LONG pId),STRING,DERIVED
SendSmtp    PROCEDURE(EmailMsgClass pMsg),BYTE,PROC,DERIVED
          END

MyMailer.Txt PROCEDURE(LONG pId)
  CODE
  IF GlobalLanguage = LNG:Portuguese
    CASE pId
    OF ETTxt:Send  ; RETURN 'Enviar'
    OF ETTxt:Sent  ; RETURN 'A mensagem foi enviada.'
    END
  END
  RETURN PARENT.Txt(pId)                    ! English and Spanish still work

MyMailer.SendSmtp PROCEDURE(EmailMsgClass pMsg)
Ok  BYTE
  CODE
  Ok = PARENT.SendSmtp(pMsg)
  Log:Sent = Ok; Log:Reason = SELF.LastErrorText; ADD(SendLog)
  RETURN Ok

Notas de Clarion

Esto no son comportamientos de emailTo: son de Clarion. Cada uno costó tiempo real de encontrar mientras se construía esto, y cada uno es de esos que no se ven hasta que muerden.

Un método llamado Clear rompe CLEAR() en todas partes

Un miembro de clase cuya etiqueta coincide con una intrínseca de Clarion redefine esa intrínseca para cada módulo que incluya el archivo. El compilador dice Redefining system intrinsic: CLEAR en el include, y después CLEAR(UnaVariable) en código que no tiene nada que ver con su clase deja de compilar.

!  In the CLASS declaration:
ClearAll             PROCEDURE       ! correct
!  Clear              PROCEDURE      ! WRONG - redefines the CLEAR intrinsic

!  With a method called Clear, this line, in code that has nothing to do
!  with e-mail, stops compiling:
  CLEAR(GlobalRequest)               ! error: No matching prototype available

Por eso las clases de buffer y de mensaje tienen ClearAll. RESET, ADD, LEN y FREE son los otros nombres de los que hay que alejarse.

Una llave dentro de un literal hay que duplicarla

{ abre el escape de repetición de Clarion: 'ab{3}' es 'abbb'. Clarion 12 deja pasar como texto una llave que no lleva dígitos detrás, así que un literal JSON escrito a mano compila ahí y en ninguna otra versión: Clarion 10 y 11 rechazan el literal entero con Invalid string (misused <...> or {...}, or literal is too long). La forma portable es {{, y es una sola llave en todas las versiones.

!  '{' opens Clarion's repeat-count escape:  'ab{3}'  IS  'abbb'.
!  So a brace that is meant to be a brace has to be doubled.

  body.Add('{"personalizations":[')     ! WRONG.  Clarion 10 and 11 refuse the
                                        ! literal: Invalid string (misused
                                        ! <...> or {...}, or literal too long)

  body.Add('{{"personalizations":[')    ! RIGHT.  One '{' in every version.

!  The URL templates handed to Row() are the same story:
  SELF.Row(ETPrv:Custom, ETOp:Stats, 0, 'GET', '{{scheme}{{host}/stats', 'days', 'When=@d')

!  A closing '}' needs nothing.  Neither does a brace inside a ! comment.

Aquí importa porque este juego de clases escribe JSON a mano y lleva las plantillas de URL de nueve proveedores. Si deriva BuildMap() para añadir un proveedor propio, duplique las llaves de la URL que pase a Row(): los marcadores se expanden igual que antes.

Un STRING ligado a una variable necesita una picture

Escrito con un literal en su lugar, el control sobrevive solo, y luego truena dentro de OPEN(Window) en cuanto la misma ventana tiene también un LIST. No se dibuja nada, así que en pantalla no hay ninguna pista de qué control tiene la culpa.

!  WRONG - a literal, on a control bound to a variable.  Survives on its own,
!  faults inside OPEN(Window) as soon as the window also holds a LIST.
         STRING(''),AT(10,130,280,10),USE(LocStatus),FONT(,8)

!  RIGHT - a picture wide enough for the variable
         STRING(@s128),AT(10,130,280,10),USE(LocStatus),FONT(,8)

La forma de encontrar uno así es abrir variantes de la ventana quitando un control cada vez: la variante que sí abre señala al culpable. Aquí lo arreglaban dos supresiones distintas — el LIST, o los STRING ligados — que es lo que dijo que era la combinación y no uno de los dos.

Ninguna picture de Clarion pasa de @s255

ENTRY(@s512) es error de compilación: Invalid picture token. En una cadena FORMAT es peor, porque FORMAT para el compilador es sólo texto y no se reporta nada. Deje los formatos de lista en @s255 y dele una variable más ancha al ENTRY si la necesita.

Un módulo MEMBER sin MAP pierde las intrínsecas

Un MAP a nivel de módulo es lo que trae BUILTINS.CLW. Sin uno — aunque esté vacío — CLIP, CHOOSE y las demás vuelven como Unknown function label, decenas de veces, que se lee como un include corrupto y no como cuatro líneas que faltan.

  MEMBER

  INCLUDE('EmailToClass.INC'),ONCE

  MAP
  END

Un método que devuelve STRING no puede liberar su propio buffer

La copia ocurre en el RETURN, así que cualquier cosa que se libere antes ya no está cuando el llamador la ve. El buffer tiene que sobrevivir al retorno, y eso quiere decir que es del objeto; y cada codificador necesita el suyo, porque se anidan.

!  A method that returns a STRING cannot free the buffer it built the answer
!  in: the copy happens at the RETURN.  So the buffer belongs to the object.
EmailMsgClass.Base64 PROCEDURE(STRING pRaw)
  CODE
  SELF.EncBuf.ClearAll()
  ! ... fill SELF.EncBuf ...
  RETURN SELF.EncBuf.Value()

!  And each encoder gets its OWN buffer, because they nest: the inner result
!  is still live while the outer call reads it.
  pOut.Add(SELF.QuotedPrintable(SELF.Utf8(pBody.Value())))

Las fuentes de Clarion tienen que ser CRLF

Un include sólo con LF se interpreta mal como Illegal data type: <CLASS> en la declaración, sin marcar nada dentro del include. Ojo con que sed -i quita el CR y escribe LF, así que una edición de una línea basta para romper un archivo que compilaba hace un minuto.

SCHANNEL pide un certificado de cliente que usted no tiene

El SMTP de Google, y Office 365, piden un certificado de cliente opcional. Sin certificado en la credencial, InitializeSecurityContext devuelve SEC_I_INCOMPLETE_CREDENTIALS (0x00090320) en vez de continuar, y el handshake se detiene. La solución es volver a emitir el mismo token — repetir sin leer más datos — y el handshake termina de forma anónima. Sin eso, toda conexión a Gmail falla.

El punto solitario

En SMTP, una línea que sólo tiene un . termina el mensaje. Una línea del cuerpo que legítimamente empiece con punto tiene entonces que mandarse con dos, y el servidor que recibe quita uno. Si esto sale mal, un mensaje se corta en silencio en la primera línea de ésas, que es justo la clase de cosa que nunca aparece en pruebas y luego le pasa a un cliente.
