myExport

Put an Export button on any browse or list. One press asks for the format, the file name and which columns to send, then writes CSV, CSV UTF-8, TSV, XML, JSON, HTML or a real Excel .xlsx workbook — or sends it straight to a printer, or builds a real, paginated PDF — in pure Clarion, with nothing to deploy.

OverviewResumen #

Drag myExport - Export button onto a browse window. That is the whole job: you get a wired-up button, a modal dialog that asks for a format, a destination and which columns to send, and nine writers behind it.

The part that makes it worth having is that you never describe your columns to it. At the moment the button is pressed it reads the LIST control's own FORMAT — which columns exist, which queue field each one shows, its heading and its picture — and pulls the values out of the queue with WHAT(). The file therefore matches the screen exactly, including columns your user re-ordered, resized or hid after the window opened.

Install & registerInstalar y registrar #

  1. Copy templates/myExport/libsrc/win/ExportClass.inc and ExportClass.clw to a folder on the Clarion redirection path (your app folder, or \clarion12\libsrc\win). They must be stored in ANSI with CRLF line endings — an LF-only copy makes the compiler report a bogus Illegal data type: EXPORTCLASS at every use site.
  2. Copy templates/myExport/template/win/myExport.tpl into your template folder.
  3. In the IDE: Setup ▸ Template Registry ▸ Register, pick myExport.tpl.
  4. Open a browse procedure's window, and from the control-template list drag myExport - Export button for a browse/list onto the window.
  5. In its prompts, set List control to export to your browse's LIST, and (for the default "every record" mode) the Browse object name — BRW1 for the first BrowseBox on the procedure.
That is the whole setup The class's LINK attribute pulls ExportClass.clw into the build, and the control template emits its own INCLUDE('ExportClass.INC'),ONCE. In a single-EXE application the global extension myExport - Global is optional — add it only if you also want to call the class from hand-written code in procedures that have no Export button. In a multi-DLL application it is required, in every app: see Multi-DLL applications. Nothing extra is needed for Email it when it's done either: MAPI32.DLL is loaded when the first e-mail is sent, not linked, so there is no MAPI32.LIB to add.

The Export buttonEl botón Exportar #

myExportButton is a #CONTROL template: dragging it onto the window drops a BUTTON and generates everything behind it. It is MULTI, so you can put several on one window — one per list, or two on the same list with different format sets.

What it generates

An object in %DataSection and, in the button's Accepted handler, this:

! in the button's Accepted embed
  Exporter1.Init(?Browse:1,Queue:Browse)     ! re-reads the list's live layout
  Exporter1.Title        = 'BrowseCustomers'
  Exporter1.Headers      = 1
  Exporter1.Pictures     = 1
  Exporter1.Allow        = 511               ! the format checkboxes, as a bit mask - all nine ticked by default
  IF Exporter1.Ask()                       ! format + folder + file name
    IF Exporter1.StartFile()
      BRW1.Reset()                           ! the top of the current sort order
      LOOP
        IF BRW1.Next() THEN BREAK .            ! Level:Notify = end of the view
        BRW1.SetQueueRecord()                ! view record -> the queue buffer
        Exporter1.AddRow()
      END
      Exporter1.EndFile()
      BRW1.ResetSort(1)                      ! refill the browse we just walked
      BRW1.UpdateWindow()
    END
  END
Two hidden embeds myExport - before the export dialog opens and myExport - after the file has been written let you seed Exporter1.FileName from your own logic, or post-process the file.

The run-time dialogEl diálogo en ejecución #

A modal window, centred, with a slate header band. It asks for exactly two things and offers three options:

  • Format — a drop list holding only the formats you ticked. Changing it retargets the file extension automatically, so Invoices.csv becomes Invoices.xlsx.
  • File name — pre-filled with <Title>_yyyymmdd<ext> in the current folder. … opens the standard Windows Save-As browser (with its own overwrite warning).
  • Include the column headings, Apply each column's picture, Open the file when it is done, Email the file when it is done (see Email it when it's done) and Summary rows: Sum / Avg / Min / Max — the template's settings, still changeable per export. The summary-row checkboxes only take effect for Excel .xlsx; they are greyed out for every other format.

Below that is the column picker, then the three options and the format's own one-line note.

The object survives for the life of the window, so the second export remembers the first one's folder, name, format and column choices.

Feedback is a modal popup, never a beep Success reports the row count and full path; a failure reports what went wrong — a folder that does not exist, a file already open in Excel, a full disk.

Una ventana modal, centrada, con una banda superior en azul pizarra. Pide exactamente dos cosas y ofrece tres opciones:

  • Formato — una lista desplegable que contiene solo los formatos que marcaste. Al cambiarlo se ajusta sola la extensión del archivo, así que Facturas.csv pasa a ser Facturas.xlsx.
  • Nombre de archivo — se propone <Title>_aaaammdd<ext> en la carpeta actual. El botón … abre el diálogo Guardar como de Windows (con su propio aviso de sobrescritura).
  • Incluir los encabezados, Aplicar el picture de cada columna, Abrir el archivo al terminar, Enviar el archivo por correo al terminar (ver Enviarlo por correo al terminar) y Filas de resumen: Sum / Avg / Min / Max — los valores de la plantilla, todavía modificables en cada exportación. Las casillas de filas de resumen solo tienen efecto en Excel .xlsx; en cualquier otro formato aparecen deshabilitadas.

Debajo está el selector de columnas, luego las tres opciones y la nota de una línea propia del formato.

El objeto vive mientras viva la ventana, así que la segunda exportación recuerda la carpeta, el nombre, el formato y la elección de columnas de la primera.

El aviso es una ventana modal, nunca un pitido Si va bien, informa del número de filas y la ruta completa; si falla, dice qué pasó — una carpeta que no existe, un archivo abierto en Excel, un disco lleno.

Email it when it's doneEnviarlo por correo al terminar #

A checkbox next to "Open the file when it is done" — tick it, and once the file is written, myExport opens a new message in whatever's registered as the default Simple MAPI client (Outlook, Windows Mail, or anything else set up that way) with the file already attached. It only opens the compose window — nothing sends silently. You still press Send.

MemberDefaultMeaning
EmailWhenDone0Attach and open a compose window after a successful export. Persisted the same way OpenWhenDone is.
EmailSubjectblankBlank = uses Title.
EmailBodyblankNote text in the new message.
EmailToFront1Try to bring the mail client's own window to the front, rather than it only flashing on the taskbar. See below.

In the dialog, "Bring email to front" sits on the same row as "Email the file when it is done" — hidden entirely until Email itself is ticked, since it has nothing to do otherwise.

Why a mail client only used to flash on the taskbar Windows deliberately won't let a background process steal the foreground outright — by design, so no application can grab focus away from whatever you're doing. Right before handing off to MAPISendMail, myExport now calls the standard, documented fix for exactly this — AllowSetForegroundWindow(-1) — telling Windows to let the next window that asks for the foreground actually have it. This works reliably when the mail client is already running; when it has to start cold from nothing, there can still be a timing window where Windows' permission lapses before the client's own window is ready to ask for it.

Skipped for Exp:Print (no file to attach), and skipped automatically for PreviewOut()'s own scratch PDF in TEMP — that one is never worth emailing.

It goes to whatever Windows says is the default client, not necessarily the one you use daily Simple MAPI reads HKEY_LOCAL_MACHINE\SOFTWARE\Clients\Mail to decide who handles this - a separate setting from the browser-style "default mail app" most people think of, and a separate one again from which mail client you personally have open. If another mail-capable program was installed more recently, it may have quietly taken that registry key over. There is no code-level way to force a specific installed client through Simple MAPI; the fix is always on the Windows side (Outlook's own "Make Outlook the default program for email" button, in File → Options → General, is the safest way to reclaim it).
32-bit callers and 64-bit Outlook do not mix Simple MAPI loads the mail client's own provider DLL directly into the calling process, so the bitness has to match. A 32-bit Clarion EXE (the normal case) cannot load a 64-bit Outlook's provider - Windows silently falls back to whatever else it can load, which can mean the wrong program opens even though the registry correctly points at Outlook. Check which one you have via C:\Program Files\Microsoft Office\ (64-bit) vs. C:\Program Files (x86)\Microsoft Office\ (32-bit). If they don't match, either install the 32-bit edition of Outlook, or override EmailFile() to drive Outlook through COM automation instead (see below) - COM automation talks to Outlook as a separate process and isn't affected by this at all.

Using something other than Simple MAPI

EmailFile(pFile) is declared VIRTUAL specifically so it can be replaced. The base class needs nothing beyond Windows itself: it finds MAPISendMail in MAPI32.DLL with LoadLibrary/GetProcAddress the first time it is called, so there is no import library to link, and a machine with no mail client at all just gets the “could not e-mail” message. A derived class can override just this one method to route through a commercial automation library instead — CapeSoft's Office Inside, for instance, whose oiOutlook.SendEmail() talks to Outlook via COM automation rather than Simple MAPI's in-process DLL loading, sidestepping the 32/64-bit mismatch entirely:

MyExportClass CLASS(ExportClass)
EmailFile           PROCEDURE(STRING pFile),PROTECTED,VIRTUAL
                  END

MyExportClass.EmailFile PROCEDURE(STRING pFile)
Outlook   &oiOutlook
subj      CSTRING(129)
  CODE
  subj = CLIP(SELF.EmailSubject)
  IF ~subj THEN subj = CLIP(SELF.Title) .
  Outlook &= NEW oiOutlook
  IF Outlook.Init()
    Outlook.SendEmail('','','',subj,CLIP(LEFT(pFile)),SELF.EmailBody,1,1)  ! pOpen=1: opens, never auto-sends
    Outlook.Kill()
  END
  DISPOSE(Outlook)

Use MyExportClass wherever you'd otherwise declare ExportClass — every other feature is inherited unchanged, only EmailFile() is different.

Una casilla junto a "Abrir el archivo al terminar" — actívala, y en cuanto el archivo se escribe, myExport abre un mensaje nuevo en lo que sea que esté registrado como cliente Simple MAPI predeterminado (Outlook, Windows Mail, o cualquier otro configurado así) con el archivo ya adjunto. Solo abre la ventana de redacción — nada se envía en silencio. Tú sigues pulsando Enviar.

En el diálogo, "Traer correo al frente" está en la misma fila que "Enviar el archivo por correo al terminar" — oculta por completo hasta que se marca Email, ya que sin eso no tiene sentido.

Por qué un cliente de correo antes solo parpadeaba en la barra de tareas Windows deliberadamente no deja que un proceso en segundo plano robe el primer plano sin más — por diseño, para que ninguna aplicación pueda quitarle el foco a lo que estés haciendo. Justo antes de pasarle el control a MAPISendMail, myExport ahora llama a la solución estándar y documentada para esto exactamente — AllowSetForegroundWindow(-1) — diciéndole a Windows que deje que la próxima ventana que pida el primer plano lo consiga de verdad. Esto funciona de forma fiable cuando el cliente de correo ya está abierto; cuando tiene que arrancar desde cero, todavía puede haber una ventana de tiempo en la que el permiso de Windows caduque antes de que la ventana propia del cliente esté lista para pedirlo.

Se omite para Exp:Print (no hay archivo que adjuntar), y se omite automáticamente para el PDF de prueba de PreviewOut() en TEMP — a ese nunca vale la pena mandarlo por correo.

Va a lo que Windows diga que es el cliente predeterminado, no necesariamente al que usas a diario Simple MAPI lee HKEY_LOCAL_MACHINE\SOFTWARE\Clients\Mail para decidir quién lo maneja — un ajuste distinto del "programa de correo predeterminado" al estilo navegador que la mayoría imagina, y distinto también de qué cliente de correo tengas tú abierto personalmente. Si se instaló otro programa con capacidad de correo más recientemente, puede haberse quedado con esa clave del registro sin avisar. No hay forma, a nivel de código, de forzar un cliente instalado específico a través de Simple MAPI; la solución siempre está del lado de Windows (el botón propio de Outlook "Make Outlook the default program for email", en Archivo → Opciones → General, es la forma más segura de recuperarlo).
Un proceso de 32 bits y un Outlook de 64 bits no se mezclan Simple MAPI carga el DLL del propio proveedor del cliente de correo directamente dentro del proceso que llama, así que los bits tienen que coincidir. Un EXE de Clarion de 32 bits (el caso normal) no puede cargar el proveedor de un Outlook de 64 bits - Windows recurre en silencio a lo que sí pueda cargar, lo que puede significar que se abra el programa equivocado aunque el registro apunte correctamente a Outlook. Comprueba cuál tienes mirando C:\Program Files\Microsoft Office\ (64 bits) frente a C:\Program Files (x86)\Microsoft Office\ (32 bits). Si no coinciden, instala la edición de 32 bits de Outlook, o redefine EmailFile() para manejar Outlook por automatización COM en su lugar (ver abajo) - la automatización COM habla con Outlook como un proceso aparte y esto no le afecta en absoluto.

Usar algo distinto de Simple MAPI

EmailFile(pFile) está declarado VIRTUAL justamente para poder reemplazarlo. La clase base no necesita nada más que Windows: busca MAPISendMail en MAPI32.DLL con LoadLibrary/GetProcAddress la primera vez que se usa, así que no hay librería de importación que enlazar, y una máquina sin cliente de correo simplemente recibe el mensaje de «no se pudo enviar». Una clase derivada puede redefinir solo este método para pasar por una librería de automatización comercial en su lugar — Office Inside de CapeSoft, por ejemplo, cuyo oiOutlook.SendEmail() habla con Outlook por automatización COM en vez de la carga de DLL en el mismo proceso de Simple MAPI, evitando por completo el problema de 32/64 bits:

MyExportClass CLASS(ExportClass)
EmailFile           PROCEDURE(STRING pFile),PROTECTED,VIRTUAL
                  END

MyExportClass.EmailFile PROCEDURE(STRING pFile)
Outlook   &oiOutlook
subj      CSTRING(129)
  CODE
  subj = CLIP(SELF.EmailSubject)
  IF ~subj THEN subj = CLIP(SELF.Title) .
  Outlook &= NEW oiOutlook
  IF Outlook.Init()
    Outlook.SendEmail('','','',subj,CLIP(LEFT(pFile)),SELF.EmailBody,1,1)  ! pOpen=1: abre, nunca envía solo
    Outlook.Kill()
  END
  DISPOSE(Outlook)

Which records get exportedQué registros se exportan #

An ABC BrowseBox queue holds only the page of rows around what is on screen — so exporting the queue would export a screenful. That is why the default is every record in the browse:

  • Every record (walks the view) — BRW1.Reset() then BRW1.Next() to the end, with BRW1.SetQueueRecord() filling the queue buffer for each row. This goes through the browse's own VIEW, so the current sort order, range limits and filters all apply — what the user narrowed the browse down to is what they get. Afterwards ResetSort(1) rebuilds the browse; it re-displays from the top of the current sort order.
  • Only the loaded rows — ExportQueue() walks the queue itself. This is the right choice for a hand-coded LIST + QUEUE, or for a file-loaded browse, and it does not disturb the browse at all.

La cola de un BrowseBox de ABC solo guarda la página de filas alrededor de lo que se ve en pantalla, así que exportar la cola exportaría una pantalla. Por eso el valor por defecto es todos los registros del browse:

  • Todos los registros (recorre la vista) — BRW1.Reset() y luego BRW1.Next() hasta el final, con BRW1.SetQueueRecord() llenando el buffer de la cola en cada fila. Esto pasa por la VIEW del propio browse, así que se respetan el orden actual, los range limits y los filtros: lo que el usuario dejó filtrado es lo que obtiene. Al terminar, ResetSort(1) reconstruye el browse; se vuelve a mostrar desde el principio del orden actual.
  • Solo las filas cargadas — ExportQueue() recorre la cola tal cual. Es la opción correcta para un LIST + QUEUE escrito a mano, o para un browse cargado por completo, y no molesta al browse en absoluto.

Multi-DLL applicationsAplicaciones multi-DLL #

One copy of ExportClass serves the whole suite, and there is nothing to configure: add the myExport - Global extension to every app in the suite and each one works out for itself whether it owns the class or imports it.

The rule it follows is the application's own External setting, the one you already set when you built the suite:

The appGlobal Properties → ExternalWhat happens
The one that owns the data (your data DLL)None external ExportClass.clw is compiled into it, and the whole class is added to that DLL's generated .EXP — so the rest of the suite can call it.
Every other app — DLLs and the EXEAll external → Dynamic Link Library The class is imported from that DLL. No copy of its code is compiled in.

Two project defines carry the decision, exactly as the ABC classes do it:

! the app that owns the class
#pragma define(_myExportLinkMode_=>1)
#pragma define(_myExportDllMode_=>0)

! every app that imports it
#pragma define(_myExportLinkMode_=>0)
#pragma define(_myExportDllMode_=>1)

Both are written into the project for you, and the export list is generated from Clarion's own class registry — so if a later version of ExportClass gains a method, the exports follow on the next generate. Nothing in the template names a mangled symbol.

The one thing you must not skip Where a class lives is a per-application decision, so only the global extension can make it — the Export button and the code template cannot. If you add the button to a procedure in a child app but forget the global extension there, that app quietly compiles its own private copy of the class again. It still works; it is just no longer sharing.

Under the bonnet

ExportClass.inc is tagged !ABCIncludeFile(MYEXPORT) on line 1, which files it in the IDE's class registry under its own category. The global extension registers that category with the ABC chain:

#AT(%BeforeGenerateApplication),WHERE(%xgDisable=0)

  #CALL(%SetCategoryLocationFromPrompts(ABC),'MYEXPORT','myExport','')
#ENDAT

  ALLOWED@F11EXPORTCLASSl                                 @?
  ...
  ZIPFINISH@F11EXPORTCLASS                                @?

Print & PDFPrint y PDF #

These two are not file-format writers so much as the same page layout engine aimed at two different outputs — a printer's device context for Print, and a hand-built PDF byte stream for PDF. Both paginate, both share the same Page Setup dialog, and neither needs Excel, Acrobat, a print driver wrapper, or any file at all in Print's case.

Print

Plain GDI: CreateDC on PrinterName (blank = the Windows default printer), then StartDoc / StartPage / TextOut / EndPage / EndDoc — one call per column per row, using the printer's own reported character metrics so columns line up. No spooler quirks to work around, no PRINTER structure to fill in by hand.

The dialog's Save to field disappears for Print — there is nothing to save — and the Export button relabels itself Print.

PDF

A genuine, minimal PDF 1.4 file assembled a line at a time: two Helvetica fonts (regular and bold), one page object and one content stream per page, a cross-reference table with real byte offsets, and a trailer — nothing borrowed from a print driver or a third-party library. The title (from Title) is set in bold at the top of page one, then the heading row, then one line of text per cell, paginating automatically as the page fills.

Every number in the file matters A PDF reader like Chrome's own viewer is far stricter about a well-formed cross-reference table, object offsets and stream /Length values than Acrobat's forgiving repair logic. This writer keeps every number that ends up in the file — object numbers, offsets, coordinates, stream lengths — on a hand-rolled, unpadded decimal conversion rather than Clarion's own default numeric-to-string behaviour, specifically so it holds up under a strict reader as well as a lenient one.
A 2,000-page ceiling, with a warning if you hit it A single PDF here holds up to 2,000 pages. Cross that, and the export doesn't fail or produce a corrupted file — it stops adding pages, finishes the file correctly with whatever fit, and shows a clear "PDF incomplete" warning (or sets PdfTruncated, checkable in code even with Confirm off) so missing rows are never silent. If you're regularly landing anywhere near that ceiling, Excel or CSV handle a data set that size far better than a several-thousand-page PDF ever will.

Number formats: decimals and negativesFormatos numéricos: decimales y negativos #

Every numeric cell is written as a real number, not text — deliberate, since that's what makes a column sortable, filterable, and usable in formulas once it lands in Excel. Left alone, though, a real number renders under Excel's own General format, which strips trailing zeros: 123.00 becomes 123. Nothing is lost — the underlying value is still exactly right, and any formula referencing it still computes correctly — but the display no longer matches what the column's own picture showed on screen.

This is fixed automatically, per column, from that column's own picture — no property to set for this half. A picture like @n-9.2 means 2 decimal places (the number after the dot is parsed as a value, not counted as characters — @n-20.10 means 10 places, not 1), and a column showing decimals gets a matching Excel number format applied to its cells, keeping 123.00 looking like 123.00. A plain integer column is untouched — General already displays it correctly, so no custom format is added, and nothing about its output changes. Columns sharing an identical picture share one format entry rather than each getting their own; the same format is applied to that column's Sum/Average/Min/Max/Count cell too, when one exists.

Turn one or more on with the Summary rows: Sum / Avg / Min / Max / Cnt checkboxes in the dialog, then tick the Tot column for whichever numeric columns should be included — the same Tot column and Toggle total button described under Choosing the columns. ! 11 data rows, headings on: data is rows 2..12
Total     =SUM(A2:A12)
Average   =AVERAGE(A2:A12)
Minimum   =MIN(A2:A12)
Maximum   =MAX(A2:A12)

The underlying value is still exactly right; it's purely cosmetic, and the tradeoff for not needing a separate style per summary kind.

Subtotal / group rowsFilas de subtotal / grupo #

The same picker's Grp column and Toggle group button (next to Tot and Toggle total) mark ONE column — any column, not just numeric ones — as the one to break on. Whenever that column's value changes between one row and the next, a bold subtotal row is inserted right there before continuing, and the very last group gets one too, once the data runs out. This only works because Summary rows already tracks Sum/Min/Max/Count per column — the subtotal machinery just resets those same running totals at every break instead of only at the very end.

The data must already be sorted by the group column A subtotal row appears every time the group column's value differs from the row before it — full stop. There is no look-ahead, no re-sorting, no grouping by similarity. If the browse isn't already ordered by that column, you'll get a new "group" every time the value happens to change, not real groups.

Whichever of Sum/Average/Min/Max are already ticked apply to the subtotal rows too — there's no separate switch for "which totals show up at a break" versus "which show up at the very end." The label repeats the pattern the grand-total row already uses: it always lands in the leftmost column (not necessarily the group column itself), reading "<label> <group value>" — e.g. "Total East" — and every other column in that row still gets a styled, bordered cell even with nothing to show, so the row's top border draws as one unbroken line across the full width instead of stopping wherever a column happens to be blank.

The grand total still comes out right Once subtotal rows exist, a naive =SUM(A2:A50) for the very last, grand-total row would double-count every group's own subtotal sitting inside that same range. Both levels use Excel's SUBTOTAL() instead of a plain function — the group rows as =SUBTOTAL(9,B2:B4), say, and the grand total as =SUBTOTAL(9,A2:A50) — specifically because SUBTOTAL() only ever ignores another cell if that cell's own formula is also SUBTOTAL(); it has no other way to recognise "this row is a subtotal." A group's own range never contains another subtotal, so its own row computes an identical value either way — using SUBTOTAL() there doesn't change what that row shows, it just makes the cell visible to the outer call. This switch only happens when a group column is actually set; a plain export without grouping still gets a plain SUM(), unchanged.

From code, the same idea as ColumnTotal():

Exporter1.ColumnGroupBy(2,1)     ! column 2 is THE group-by column - only one at a time
Exporter1.Totals = 1              ! Sum, both at each break and at the grand total
Exporter1.ColumnTotal(4,1)        ! sum column 4 within each group

ColumnGroupBy() is single-select — ticking a new column clears whichever one was ticked before, the same way a radio button would, since only one break column makes sense at a time.

La misma columna Grp del selector y el botón Toggle group (junto a Tot y Toggle total) marcan UNA columna — cualquiera, no solo las numéricas — como aquella por la que se hace el corte. Cada vez que el valor de esa columna cambia entre una fila y la siguiente, se inserta ahí mismo una fila de subtotal en negrita antes de seguir, y el último grupo también recibe una, en cuanto se acaban los datos. Esto funciona porque Filas de resumen ya lleva el Sum/Mín/Máx/Conteo por columna — el mecanismo de subtotal solo reinicia esos mismos acumulados en cada corte en vez de solo al final.

Los datos deben venir ya ordenados por la columna de grupo Aparece una fila de subtotal cada vez que el valor de la columna de grupo difiere del de la fila anterior — así de simple. No hay adelanto de lectura, ni reordenamiento, ni agrupación por similitud. Si el browse no viene ya ordenado por esa columna, tendrás un "grupo" nuevo cada vez que el valor cambie, no grupos reales.

Los que ya estén marcados de Sum/Average/Min/Max se aplican también a las filas de subtotal — no hay un interruptor aparte para "cuáles aparecen en un corte" frente a "cuáles aparecen al final". La etiqueta repite el mismo patrón que ya usa la fila de gran total: siempre cae en la columna más a la izquierda (no necesariamente la columna de grupo en sí), con el texto "<etiqueta> <valor de grupo>" — por ejemplo "Total East" — y cualquier otra columna en esa fila igual recibe una celda con estilo y borde aunque no tenga nada que mostrar, para que el borde superior de la fila se dibuje como una sola línea continua en todo el ancho en vez de cortarse donde una columna esté vacía.

El gran total sigue saliendo correcto En cuanto existen filas de subtotal, un ingenuo =SUM(A2:A50) para la última fila, la del gran total, contaría dos veces el subtotal de cada grupo que ya está dentro de ese mismo rango. Ambos niveles usan SUBTOTAL() de Excel en vez de una función normal — las filas de grupo como =SUBTOTAL(9,B2:B4), por ejemplo, y el gran total como =SUBTOTAL(9,A2:A50) — precisamente porque SUBTOTAL() solo ignora otra celda si la fórmula de esa celda es también SUBTOTAL(); no tiene otra manera de reconocer "esta fila es un subtotal". El rango propio de un grupo nunca contiene otro subtotal, así que su propia fila calcula un valor idéntico de cualquier forma — usar SUBTOTAL() ahí no cambia lo que muestra esa fila, solo hace visible la celda a la llamada externa. Este cambio solo ocurre cuando de verdad hay una columna de grupo puesta; una exportación normal sin agrupar sigue recibiendo un SUM() normal, sin cambios.

Desde código, la misma idea que ColumnTotal():

Exporter1.ColumnGroupBy(2,1)     ! la columna 2 es LA columna de grupo - solo una a la vez
Exporter1.Totals = 1              ! Suma, tanto en cada corte como en el gran total
Exporter1.ColumnTotal(4,1)        ! suma la columna 4 dentro de cada grupo

ColumnGroupBy() es de selección única — marcar una columna nueva quita la que estuviera marcada antes, igual que un botón de radio, porque solo tiene sentido una columna de corte a la vez.

Multiple sheets in one workbookVarias hojas en un mismo libro #

Two different ways to end up with more than one tab in the same .xlsx, for two different situations — combining several separate lists into one workbook you assemble yourself, or automatically splitting one already-grouped export into a sheet per group. Both are code-driven only: there is no dialog for this, because several different lists at once have no single format/column choice a picker could sensibly ask about.

Combining several lists yourself

Four extra methods bracket the familiar StartFile()/AddRow()/EndFile() loop you already know, once per sheet, inside one outer pair:

Exporter1.Fmt = Exp:XLSX
Exporter1.FileName = 'C:\reports\school.xlsx'

IF Exporter1.StartWorkbook()
  Exporter1.Init(?List1, StudentsQueue)
  IF Exporter1.StartSheet('Students')
    ! the SAME AddRow() loop you already write for a single-sheet export
    LOOP
      IF BRW1.Next() THEN BREAK .
      Exporter1.AddRow()
    END
    Exporter1.EndSheet()
  END

  Exporter1.Init(?List2, CoursesQueue)                     ! rebind for the next sheet's own columns
  IF Exporter1.StartSheet('Courses')
    LOOP
      IF BRW2.Next() THEN BREAK .
      Exporter1.AddRow()
    END
    Exporter1.EndSheet()
  END

  Exporter1.EndWorkbook()                                  ! assembles and writes the actual file
END

Each sheet keeps its own independent column selection, headers, pictures, and totals/subtotal grouping — because each one runs through its own Init() and its own StartSheet()/AddRow()/EndSheet(), exactly like a standalone export does. Tab order matches call order; a duplicate tab name (Excel refuses two identical ones) gets " (2)", " (3)" appended automatically, the same way Windows renames a second copy of a file.

MethodMeaning

EndSheet()Like the worksheet half of EndFile(), but stashes the sheet instead of writing to disk.

Splitting one grouped export automatically

A different question: rather than combining several browses, you have one grouped export (see Subtotal / group rows) and want every group to also land on its own tab, in addition to the normal, single main sheet with its inline subtotal rows. One property:

Exporter1.SplitByGroup = 1        ! needs a Grp column already set, same as subtotal rows

Nothing else changes about how you call the class — still the plain StartFile()/AddRow()/EndFile() loop, one pass over the browse. Internally, every AddRow() call writes the row twice: once into the main sheet (unchanged), and once into a second, entirely separate buffer for whichever group is currently open. A break closes that buffer off — with its own Sum/Avg/Min/Max row, using the same per-group running totals the inline subtotal rows already track — and stashes it as its own named sheet. The main sheet always ends up as the first tab regardless of the order sheets get stashed internally, since it's meant to stay the workbook's obvious default view.

In the dialog, this is the "Split into sheets" checkbox sitting on the same row as the Summary rows checkboxes — greyed out, like they are, for anything other than Excel .xlsx.

Building a code template for this

Since combining several lists is code-driven, a Clarion code template (#CODE, the same kind as an "insert this snippet where I click" template) can generate the StartWorkbook/Init/StartSheet/loop/EndSheet/EndWorkbook wiring for you, the same way the Export button's own template generates its dialog wiring. The shape of it:

  • A repeating prompt group — one row per sheet, each with its own List control, Browse object and sheet name — so the developer adds sheets the same way they'd add rows to any other repeating list in the Clarion IDE, in Template Language: #PROMPT('Sheets:',FROM(%group)),MULTI ... #ENDPROMPT, with a nested #PROMPT('List control:',CONTROL) per row.
  • An #ATSTART block that walks the group with #FOR(%group)...#ENDFOR once, at generation time, auto-detecting each row's queue from its List control's own FROM() attribute — the same trick the existing single-list export template already uses, via EXTRACT(%ControlStatement,'FROM',1).
  • The actual code-emission section walks the same group a second time, emitting one Init/StartSheet/LOOP/EndSheet block per row, bracketed by a single StartWorkbook()/EndWorkbook() pair.
This is a pattern to build, not something bundled with the class Unlike everything else on this page, a repeating-group code template is Template Language, not Clarion code — a genuinely different scripting system, and one that needs registering and testing in your own environment before trusting it. Treat the shape above as a starting point, not a drop-in file.

Ambas son solo por código: no hay diálogo para esto, porque varias listas distintas a la vez no tienen una única elección de formato/columnas que un selector pudiera preguntar con sentido.

Dividir automáticamente una exportación agrupada

Una pregunta distinta: en vez de combinar varios browses, tienes una exportación agrupada (ver Filas de subtotal / grupo) y quieres que cada grupo también caiga en su propia pestaña, además de la hoja principal normal con sus filas de subtotal en línea. Una propiedad:

Nada más cambia en cómo llamas a la clase — sigue siendo el mismo bucle StartFile()/AddRow()/EndFile(), una sola pasada por el browse. Por dentro, cada llamada a AddRow() escribe la fila dos veces: una en la hoja principal (sin cambios), y otra en un segundo búfer, totalmente aparte, para el grupo que esté abierto en ese momento. Un corte cierra ese búfer — con su propia fila Sum/Avg/Min/Max, usando los mismos totales por grupo que ya llevan las filas de subtotal en línea — y lo guarda como su propia hoja con nombre. How it reads the listCómo lee la lista #

ScanColumns walks the control's format and builds a small queue of exportable columns:

LOOP c = 1 TO 512
  ex = ?List{PROPLIST:Exists,c}   ; IF ~ex THEN BREAK .
  f  = ?List{PROPLIST:FieldNo,c}  ; IF ~f  THEN CYCLE .   ! decoration, not data
  w  = ?List{PROPLIST:Width,c}                                ! 0 = the user hid it
  h  = ?List{PROPLIST:Header,c}                               ! becomes the file's heading
  p  = ?List{PROPLIST:Picture,c}                              ! formats the value
END
! ...and then, per row:
value = FORMAT(WHAT(Queue:Browse,f),p)

This is the same recipe the shipped brwext.clw uses to read a browse cell, so it behaves the way Clarion itself does.

Read every property into a LONG first A Clarion property read returns a string, and the string '0' is logically true. IF ~?List{PROPLIST:Width,c} therefore never fires on a hidden column, and IF ?List{PROPLIST:Icon,c} is true for every column. Assigning to a LONG first forces the numeric conversion. ExportClass does this; it is worth remembering in your own code.

ScanColumns recorre el formato del control y arma una pequeña cola con las columnas exportables:

LOOP c = 1 TO 512
  ex = ?List{PROPLIST:Exists,c}   ; IF ~ex THEN BREAK .
  f  = ?List{PROPLIST:FieldNo,c}  ; IF ~f  THEN CYCLE .   ! adorno, no dato
  w  = ?List{PROPLIST:Width,c}                                ! 0 = el usuario la ocultó
  h  = ?List{PROPLIST:Header,c}                               ! será el encabezado del archivo
  p  = ?List{PROPLIST:Picture,c}                              ! formatea el valor
END
! ...y después, por cada fila:
valor = FORMAT(WHAT(Queue:Browse,f),p)

Es la misma receta que usa el brwext.clw que viene con Clarion para leer una celda de un browse, así que se comporta como el propio Clarion.

Lee cada propiedad en un LONG primero Leer una propiedad en Clarion devuelve una cadena, y la cadena '0' es lógicamente verdadera. Por eso IF ~?List{PROPLIST:Width,c} nunca se cumple en una columna oculta, y IF ?List{PROPLIST:Icon,c} es verdadero para todas las columnas. Asignar primero a un LONG fuerza la conversión numérica. ExportClass lo hace; conviene recordarlo en tu propio código.

ArchitectureArquitectura #

  • One growable buffer holds the file being built (Buf), doubling as needed. A second (Arc) assembles the ZIP; a third (U8) is UTF-8 scratch.
  • Escaping is chunked. Each escaper copies the longest clean run in one Cat and only then emits an escape, so ordinary data costs one append per cell rather than one per character.
  • UTF-8 conversion is skipped when it is a no-op. Pure-ASCII text already is valid UTF-8, so the buffer is scanned once and copied straight through; only text with high bytes goes through MultiByteToWideChar / WideCharToMultiByte.
  • Writing is atomic. The buffer goes to a .tmp file next to the real one (CreateFileA / WriteFile / CloseHandle from MODULE('win32'), the whole buffer in one write), then MoveFileExA swaps it into the real name in one step. A viewer that already has the previous export open — which is the normal case, since OpenWhenDone opens every export — keeps reading its own already-open handle to the old content until it re-opens the path, rather than catching the file mid-write.
  • The class knows nothing about ABC. It takes a control number and a queue; the browse walk lives in the generated code. So it works just as well in a legacy or hand-coded app.
  • Un búfer que crece guarda el archivo que se está armando (Buf), duplicando su tamaño cuando hace falta. Un segundo (Arc) monta el ZIP; un tercero (U8) es el borrador UTF-8.
  • El escapado va por tramos. Cada escapador copia de una sola vez el tramo limpio más largo y solo entonces emite un escape, así que los datos normales cuestan un append por celda en vez de uno por carácter.
  • La conversión a UTF-8 se salta cuando no hace nada. El texto puramente ASCII ya es UTF-8 válido, así que se recorre el búfer una vez y se copia tal cual; solo el texto con bytes altos pasa por MultiByteToWideChar / WideCharToMultiByte.
  • Escribir es atómico. El búfer va primero a un archivo .tmp junto al definitivo (CreateFileA / WriteFile / CloseHandle desde MODULE('win32'), todo el búfer en una sola escritura), y luego MoveFileExA lo intercambia por el nombre real en un solo paso. Un lector que ya tenga abierta la exportación anterior — el caso normal, porque OpenWhenDone abre cada exportación — sigue leyendo su propio identificador ya abierto al contenido viejo hasta que vuelve a abrir la ruta, en vez de sorprender al archivo a medio escribir.
  • La clase no sabe nada de ABC. Recibe un número de control y una cola; el recorrido del browse vive en el código generado. Por eso funciona igual de bien en una app legacy o escrita a mano.

Driving it from codeDesde tu propio código #

A hand-coded LIST over a plain QUEUE needs three lines:

Exporter1.Init(?List,MyQueue)
Exporter1.Title = 'Invoices'
Exporter1.Run()                              ! dialog, then write

To write a file with no dialog at all — a nightly job, a "mail this to me" button:

Exporter1.Init(?List,MyQueue)
Exporter1.Title        = 'Invoices'
Exporter1.Fmt          = Exp:XLSX
Exporter1.FileName     = 'C:\reports\invoices.xlsx'
Exporter1.Confirm      = 0                   ! no popup
Exporter1.OpenWhenDone = 0                   ! do not launch Excel
IF ~Exporter1.ExportQueue()
  ! Exporter1.ErrText says why
END

To also preset which columns get Sum/Average/Min/Max rows, see the code example under Summary rows — same idea, ColumnTotal() instead of ColumnUse().

To export something that is not a queue walk at all — a VIEW, a file, a computed set — drive the three writing methods yourself:

IF Exporter1.Ask()
  IF Exporter1.StartFile()
    ! fill the queue BUFFER however you like, then:
    Exporter1.AddRow()
    ...
    Exporter1.EndFile()
  END
END

Un LIST escrito a mano sobre una QUEUE normal necesita tres líneas:

Exporter1.Init(?List,MyQueue)
Exporter1.Title = 'Facturas'
Exporter1.Run()                              ! diálogo y luego escribir

Para escribir un archivo sin diálogo alguno — un proceso nocturno, un botón de "mándame esto":

Exporter1.Init(?List,MyQueue)
Exporter1.Title        = 'Facturas'
Exporter1.Fmt          = Exp:XLSX
Exporter1.FileName     = 'C:\reportes\facturas.xlsx'
Exporter1.Confirm      = 0                   ! sin aviso
Exporter1.OpenWhenDone = 0                   ! no abrir Excel
IF ~Exporter1.ExportQueue()
  ! Exporter1.ErrText dice por qué
END

Para elegir o fijar las columnas desde código, sin tocar el diálogo:

Exporter1.Init(?List,MyQueue)
Exporter1.SelectAll(0)                       ! empezar sin ninguna
Exporter1.ColumnUse(1,1)                     ! solo las columnas 1, 2 y 5
Exporter1.ColumnUse(2,1)
Exporter1.ColumnUse(5,1)
Exporter1.ColumnRename(2,'Nombre del cliente')
Exporter1.ColumnPicture(5,'')             ! valor crudo, sin picture
Exporter1.AllowColumns = 0                   ! y que el usuario no lo cambie
Exporter1.Run()

Para fijar también qué columnas llevan filas de Suma/Promedio/Mín/Máx, mira el ejemplo de código en Filas de resumen — la misma idea, con ColumnTotal() en vez de ColumnUse().

Para exportar algo que no es un recorrido de cola — una VIEW, un archivo, un conjunto calculado — maneja tú mismo los tres métodos de escritura:

IF Exporter1.Ask()
  IF Exporter1.StartFile()
    ! llena el BUFFER de la cola como quieras, y luego:
    Exporter1.AddRow()
    ...
    Exporter1.EndFile()
  END
END

TroubleshootingSolución de problemas #

SymptomCause and fix
Illegal data type: EXPORTCLASSExportClass.inc has LF-only line endings, or is UTF-8. Save it as ANSI with CRLF.
The button generates nothingThe template could not find a queue. Either the LIST has no FROM() attribute (it is bound at run time) — fill in the Queue prompt — or the List control prompt is empty.
Only a screenful of rows came outRecords is set to "only the rows currently loaded". Switch it to "every record in the browse" and set the Browse object.
Unknown identifier: BRW1 when compilingThe Browse object prompt does not match the real BrowseBox object name. Check the BrowseBox extension's Classes tab.
Accents look wrong in ExcelUse CSV UTF-8 rather than plain CSV — Excel needs the BOM. Or export .xlsx, which is always UTF-8.
Excel shows numbers as textThe column has a non-@N picture, so it is treated as text on purpose. Untick Apply each column's picture, or give the column an @N picture.
A summary row (Sum/Avg/Min/Max) does not appearCheck three things: the format is Excel .xlsx (the checkboxes are disabled for every other format), at least one of the four is ticked, and at least one numeric column has Tot ticked. See Summary rows.
A column you wanted is missingIt is un-ticked in the picker — hidden and icon columns start that way. Tick it, or untick Start with visible columns only so they all start on.
A rename or tick was forgotten between exportsThe list's layout changed (a column added, removed, re-sized or re-ordered), so the column list was rebuilt. Expected.
"A Clarion picture starts with @"The picture typed into the column popup is not a picture. Leave it blank for the raw value.
"Could not create …"The folder does not exist, or the file is open in Excel. The popup names the path.
The browse jumps to the top after exportingExpected: walking the view then ResetSort(1) re-displays from the top of the current sort order. Use the queue-only mode if that matters more than completeness.
Multi-DLL: Unresolved external … EXPORTCLASSThe app is set to import the class but the DLL that owns it does not export it. Add the myExport - Global extension to the owning app too and re-generate it, so its .EXP gets the class. See Multi-DLL applications.
Multi-DLL: no EXPORTCLASS lines in the generated .EXPThe IDE's class registry has not seen ExportClass.inc. Press Refresh Application Builder Class Information on the Global Properties Classes tab, check the file is on the redirection path, and generate again.
Multi-DLL: every DLL still carries its own copyThe global extension is missing from the child apps, so nothing sets _myExportDllMode_ there. It has to be added per application — the button cannot do it.
