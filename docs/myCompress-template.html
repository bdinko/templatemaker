myCompress

A self-contained compression library for Clarion — DEFLATE, zlib and gzip implemented in pure Clarion. Compress and decompress memory buffers and files, in formats that interoperate with gzip, 7-Zip, browsers and .NET. No DLL, no external library.

Una biblioteca de compresión autosuficiente para Clarion — DEFLATE, zlib y gzip implementados en Clarion puro. Comprime y descomprime búferes de memoria y archivos, en formatos que interoperan con gzip, 7-Zip, los navegadores y .NET. Sin DLL, sin bibliotecas externas.

RFC 1951/1950/1952 · memory + files · gzip/zlib/raw · one global object · pure ClarionRFC 1951/1950/1952 · memoria + archivos · gzip/zlib/raw · un objeto global · Clarion puro

OverviewResumen #

myCompress adds one global object to your application — a CompressClass instance you can reach from any procedure or embed — and through it compress or decompress data, either in memory or on disk, using the standard DEFLATE family of formats.

It is a sibling of myQRDraw and myBarcodeGen: a self-contained ANSI Clarion class that does real work with no outside dependency. The codec is a from-scratch implementation of RFC 1951 (DEFLATE) with the RFC 1950 (zlib) and RFC 1952 (gzip) wrappers, so a .gz it writes opens in any tool, and it reads any .gz / zlib / raw stream those tools produce.

Install & registerInstalar y registrar #

  1. Copy templates/myCompress/libsrc/win/CompressClass.inc and CompressClass.clw to a folder on the Clarion redirection path (your app folder, or \clarion12\libsrc\win). They must be stored in ANSI, not UTF-8.
  2. Copy templates/myCompress/template/win/myCompress.tpl into your template folder.
  3. In the IDE: Setup ▸ Template Registry ▸ Register, pick myCompress.tpl.
  4. On the application's global Extensions, add myCompress - Global Compressor (once). Set the object name (default Zip), and optional default format and level.
That's the whole setup The class's LINK attribute pulls CompressClass.clw into the build automatically; the ONCE include guard means it is safe even if another template also pulls it in. The object is multi-DLL aware out of the box (defined in the root DLL, imported elsewhere).

Quick startInicio rápido #

From any embed, call the global object (named in the prompts; Zip below):

! ---- memory: compress a string, then get it back ----
loc:raw    STRING(5000)
loc:rawLen LONG
packed     &STRING
n          LONG
back       STRING(5000)
  CODE
  loc:raw    = '…whatever bytes you want to pack…'
  loc:rawLen = 5000                          ! the REAL length — see the binary note
  packed &= NEW STRING(Zip.MaxCompressed(loc:rawLen))
  n = Zip.Compress(loc:raw, loc:rawLen, packed)      ! n = packed byte count, or -1
  IF n > 0
    Zip.Decompress(packed, n, back)                  ! back now equals loc:raw
  END
  DISPOSE(packed)

! ---- files: one call each way ----
  IF Zip.CompressFile('report.txt', 'report.txt.gz')
    ! report.txt.gz now opens in 7-Zip / gunzip / any browser
  END
  IF Zip.DecompressFile('archive.gz', 'archive.out')   ! reads any standard .gz
  END
Always pass the length — never rely on LEN() A Clarion STRING is fixed-length and space-padded; it does not remember how many bytes are "real", and compressed data contains 0s and spaces like any other byte. Every method here is length-explicit: you pass a LONG length in and get a LONG length back. Store that length next to the bytes (e.g. in a separate field, or a 4-byte prefix) — if you let trailing spaces creep in, the data is corrupt.

Desde cualquier embed, llama al objeto global (el nombre lo pones en los prompts; abajo, Zip):

Pasa siempre la longitud — nunca confíes en LEN() Un STRING de Clarion es de longitud fija y se rellena con espacios; no recuerda cuántos bytes son "de verdad", y los datos comprimidos contienen 0s y espacios como cualquier otro byte. Todos los métodos de aquí son explícitos en la longitud: pasas un LONG de entrada y recibes un LONG de vuelta. Guarda esa longitud junto a los bytes (en otro campo, o como prefijo de 4 bytes) — si dejas que se cuelen espacios finales, los datos quedan corruptos.

Compressing memoryComprimir en memoria #

The two memory methods are length-explicit and write into a caller-supplied output buffer:

  • Compress(*STRING pIn, LONG pInLen, *STRING pOut) — returns the compressed byte count, or -1 on error. pOut must be at least Zip.MaxCompressed(pInLen) bytes.
  • Decompress(*STRING pIn, LONG pInLen, *STRING pOut) — returns the original byte count, or -1. pOut must be big enough for the decompressed data (you generally know this from your own format, or store it alongside the compressed blob).
  • MaxCompressed(LONG pInLen) — the safe size to allocate for a compress output buffer (input may slightly expand for incompressible data, plus header/trailer).

Any memory, not just strings. A *STRING parameter accepts a STRING you overlay on anything — a GROUP, a queue record, a BLOB you have loaded — so you can compress arbitrary structures:

MyRec  GROUP
Id       LONG
Name     STRING(60)
…
       END
MyRecS STRING(SIZE(MyRec)),OVER(MyRec)        ! a byte view over the group
  CODE
  n = Zip.Compress(MyRecS, SIZE(MyRec), packed)

Los dos métodos de memoria son explícitos en la longitud y escriben en un búfer de salida que tú proporcionas:

  • Compress(*STRING pIn, LONG pInLen, *STRING pOut) — devuelve la cantidad de bytes comprimidos, o -1 si hay error. pOut debe tener al menos Zip.MaxCompressed(pInLen) bytes.
  • Decompress(*STRING pIn, LONG pInLen, *STRING pOut) — devuelve la cantidad de bytes originales, o -1. pOut debe ser lo bastante grande para los datos descomprimidos (normalmente lo sabes por tu propio formato, o lo guardas junto al bloque comprimido).
  • MaxCompressed(LONG pInLen) — el tamaño seguro que hay que reservar para el búfer de salida de una compresión (los datos incompresibles pueden crecer un poco, más la cabecera y el cierre).

Cualquier memoria, no solo cadenas. Un parámetro *STRING acepta un STRING superpuesto sobre lo que sea — un GROUP, el registro de una cola, un BLOB que hayas cargado — así que puedes comprimir estructuras arbitrarias:

MyRec  GROUP

Compressing filesComprimir archivos #

The file methods read the whole source file, run it through the same engine, and write the result — returning 1 on success, 0 on failure (with Zip.ErrText set):

  • CompressFile(STRING pSrc, STRING pDst) — writes pDst in the current Format (gzip by default, so name it .gz).
  • DecompressFile(STRING pSrc, STRING pDst) — auto-detects gzip / zlib / raw and writes the decoded bytes.
Whole-file in memory (this release) Files are loaded fully into memory for v1, which is ideal for documents, reports and exports up to tens of MB. True chunked streaming for multi-GB files is a planned enhancement; until then, size your expectations to available memory.

Los métodos de archivo leen el archivo de origen completo, lo pasan por el mismo motor y escriben el resultado — devolviendo 1 si va bien y 0 si falla (con Zip.ErrText puesto):

  • CompressFile(STRING pSrc, STRING pDst) — escribe pDst en el Format actual (gzip por defecto, así que ponle extensión .gz).
  • DecompressFile(STRING pSrc, STRING pDst) — detecta solo si es gzip / zlib / raw y escribe los bytes decodificados.
Archivo entero en memoria (en esta versión) En la v1 los archivos se cargan completos en memoria, lo cual va perfecto para documentos, informes y exportaciones de hasta decenas de MB. El streaming real por trozos para archivos de varios GB está planeado; hasta entonces, ajusta tus expectativas a la memoria disponible.

Formats & interopFormatos e interoperabilidad #

Set Zip.Format before a call (or pick the default in the prompts). The three formats are the standard DEFLATE family:

FormatEquateWrapperReads / writes with
gzipCmp:Gzip (2)10-byte header + CRC32 + ISIZEgzip / gunzip, 7-Zip, browsers, .NET GZipStream, *.gz
zlibCmp:Zlib (1)2-byte header + Adler32zlib, .NET ZLibStream, PNG/HTTP payloads
rawCmp:Raw (0)none — bare DEFLATE bitstream.NET DeflateStream, embedding in your own container

Decompression auto-detects — Decompress / DecompressFile sniff the gzip magic (1F 8B) and the zlib header check, falling back to raw DEFLATE — so you do not have to know which format a blob is in to read it.

Compression ratio The compressor currently uses fixed Huffman coding (plus LZ77 matching), which every decoder reads but which is a little larger than zlib's best (zlib adds dynamic Huffman). Decompression already handles dynamic-Huffman input from any encoder. Dynamic-Huffman output for tighter ratios is the next planned step.

Pon Zip.Format antes de una llamada (o elige el valor por defecto en los prompts). Los tres formatos son la familia estándar de DEFLATE:

FormatoEquateEnvolturaLee / escribe con
gzipCmp:Gzip (2)cabecera de 10 bytes + CRC32 + ISIZEgzip / gunzip, 7-Zip, navegadores, GZipStream de .NET, *.gz
zlibCmp:Zlib (1)cabecera de 2 bytes + Adler32zlib, ZLibStream de .NET, contenidos PNG/HTTP

La descompresión detecta sola el formato — Decompress / DecompressFile olfatean la firma de gzip (1F 8B) y la comprobación de cabecera de zlib, y si no, asumen DEFLATE crudo — así que no necesitas saber en qué formato viene un bloque para leerlo.

Ratio de compresión El compresor usa por ahora codificación Huffman fija (más el emparejado LZ77), que todos los decodificadores leen pero que sale un poco más grande que lo mejor de zlib (zlib añade Huffman dinámico). La descompresión ya maneja entrada con Huffman dinámico de cualquier codificador. Producir Huffman dinámico a la salida, para ratios más ajustados, es el siguiente paso previsto.

ArchitectureArquitectura #

templates/myCompress/ ├─ CompressClass.inc the class: config, equates, method prototypes ├─ CompressClass.clw the engine (inflate, deflate, containers, checksums) └─ myCompress.tpl one global extension (adds the shared object) designer/CompressCore/ the .NET golden-vector oracle (validation)

The class is self-contained the same way myQRDraw's encoder is: a CLASS,TYPE,MODULE,LINK whose .clw opens with a bare MEMBER and a module-level MAP (so the BUILTINS.CLW intrinsics and the Win32 file calls resolve). All working state — buffers, the bit accumulators, the LZ77 hash chains, the Huffman decode tables — lives in class members, so the single global instance is reusable and the codec has no global side-effects.

The bit layout follows the RFC exactly: DEFLATE packs bits LSB-first, while Huffman codes are defined MSB-first, so the writer reverses each code's bits before packing and the reader decodes canonically bit-by-bit. Output grows a class-owned buffer; for back-reference copies the engine reserves space up front so the buffer never moves mid-copy (which also makes overlapping runs — the heart of run-length compression — fall out for free).

templates/myCompress/ ├─ CompressClass.inc la clase: configuración, equates, prototipos ├─ CompressClass.clw el motor (inflate, deflate, contenedores, sumas) └─ myCompress.tpl una extensión global (agrega el objeto compartido) designer/CompressCore/ el oráculo .NET de vectores dorados (validación)

La clase es autosuficiente igual que el codificador de myQRDraw: un CLASS,TYPE,MODULE,LINK cuyo .clw abre con un MEMBER pelado y un MAP a nivel de módulo (para que resuelvan las funciones intrínsecas de BUILTINS.CLW y las llamadas de archivo de Win32). Todo el estado de trabajo — búferes, los acumuladores de bits, las cadenas hash de LZ77, las tablas de decodificación Huffman — vive en miembros de la clase, así que la única instancia global es reutilizable y el códec no tiene efectos secundarios globales.

La disposición de bits sigue la RFC al pie de la letra: DEFLATE empaqueta los bits de menos a más significativo, mientras que los códigos Huffman se definen de más a menos, así que el escritor invierte los bits de cada código antes de empaquetarlo y el lector decodifica canónicamente bit a bit. La salida hace crecer un búfer propio de la clase; para las copias de retro-referencia el motor reserva espacio por adelantado para que el búfer nunca se mueva a mitad de una copia (lo que además hace que las repeticiones solapadas — el corazón de la compresión por longitud de series — salgan gratis).

C fast-path (4× faster)Vía rápida en C (4× más rápido) #

The pure-Clarion codec is fast enough for most work, but for big files or high throughput there is an optional C engine — mc.c, our own DEFLATE port — that compiles with Clarion's own C compiler and makes compression about 4× faster, with no external DLL and no third-party library.

EngineCompress (4 MB, level 6)DecompressRatio
Pure Clarion (default)~844 ms~15 ms491 KB
C fast-path~200 ms~15 ms485 KB (full 32 KB window)

It is the same algorithm in C — a clean-room port of our Clarion Deflate, not miniz/zlib/StringTheory — so it produces byte-compatible output (the engines interoperate freely: compress with one, decompress with the other). C also has no Clarion 64 KB-array limit, so the matcher uses the full 32 KB DEFLATE window, giving a slightly better ratio as well.

Turning it on

Pick it in the extension — no code edits:

  1. Copy the C engine files to the Clarion redirection path, alongside the base CompressClass.inc/.clw: CompressClassC.inc, CompressClassC.clw, and mc.c.
  2. In the myCompress - Global Compressor extension, set Compression engine to C fast-path.
  3. Generate and build. Your code is unchanged — same object name, same API.
How the switch works — it's a subclass CompressClassC is a thin subclass of CompressClass that PRAGMA('compile(mc.c)')s the C engine and overrides the virtual Wrap / Unwrap entry points to call it; the public API is inherited unchanged. The engine prompt just declares the global object as CompressClass (pure Clarion) or CompressClassC (C fast-path) — so the choice lives in the template, and a pure-Clarion app pulls in no mc.c and no subclass at all.
Single-threaded The C engine uses file-scope work tables, so it is single-threaded. If you compress from multiple threads concurrently, leave the C fast-path off and use the per-instance pure-Clarion engine.

El códec en Clarion puro es suficientemente rápido para casi todo, pero para archivos grandes o mucho volumen existe un motor en C opcional — mc.c, nuestro propio DEFLATE portado — que compila con el propio compilador de C de Clarion y hace la compresión unas 4× más rápida, sin DLL externa y sin bibliotecas de terceros.

MotorComprimir (4 MB, nivel 6)DescomprimirTamaño
Clarion puro (por defecto)~844 ms~15 ms491 KB
Vía rápida en C~200 ms~15 ms485 KB (ventana completa de 32 KB)

Es el mismo algoritmo en C — un port limpio de nuestro Deflate de Clarion, no miniz/zlib/StringTheory — así que produce una salida compatible byte a byte (los dos motores interoperan libremente: comprime con uno y descomprime con el otro). Además, en C no existe el límite de arreglos de 64 KB de Clarion, así que el buscador usa la ventana DEFLATE completa de 32 KB, lo que da un ratio incluso algo mejor.

Cómo activarlo

Se elige en la extensión — sin tocar código:

  1. Copia los archivos del motor en C al camino de redirección, junto a los CompressClass.inc/.clw base: CompressClassC.inc, CompressClassC.clw y mc.c.
  2. En la extensión myCompress - Global Compressor, pon Compression engine en C fast-path.
  3. Genera y compila. Tu código no cambia — mismo nombre de objeto, misma API.
Cómo funciona el cambio — es una subclase CompressClassC es una subclase fina de CompressClass que hace PRAGMA('compile(mc.c)') del motor en C y redefine los puntos de entrada virtuales Wrap / Unwrap para llamarlo; la API pública se hereda sin cambios. El prompt del motor simplemente declara el objeto global como CompressClass (Clarion puro) o como CompressClassC (vía rápida en C) — así que la elección vive en la plantilla, y una app en Clarion puro no arrastra ni mc.c ni la subclase.
De un solo hilo El motor en C usa tablas de trabajo a nivel de archivo, así que es de un solo hilo. Si comprimes desde varios hilos a la vez, deja apagada la vía rápida en C y usa el motor en Clarion puro, que es por instancia.

The .NET oracleEl oráculo .NET #

Clarion cannot be run from CI, so — as with QrCodeCore and BarcodeCore — a small .NET tool, designer/CompressCore/, is the independent reference. .NET's own GZipStream / ZLibStream / DeflateStream are the validated encoder/decoder, so there is nothing to re-implement; the tool closes the loop both ways:

  • INFLATE test — .NET compresses a corpus; the Clarion DecompressFile must reproduce the original bytes.
  • DEFLATE test — Clarion CompressFile writes a .gz; .NET decompresses it and confirms it matches.
# generate golden vectors (caseN.bin + caseN.bin.gz/.zz/.raw + manifest)
dotnet run --project designer/CompressCore -- vectors ./vectors
# …have the Clarion app DecompressFile each .bin.gz and CompressFile each .bin to .bin.cgz…
dotnet run --project designer/CompressCore -- verify  ./vectors    # checks the Clarion gzip output

The corpus deliberately spans the code paths: empty, single byte, long compressible text, long runs, binary with NUL bytes, incompressible random data, and an all-zero buffer.

Clarion no se puede ejecutar desde un CI, así que — igual que con QrCodeCore y BarcodeCore — una pequeña herramienta .NET, designer/CompressCore/, hace de referencia independiente. Los propios GZipStream / ZLibStream / DeflateStream de .NET son el codificador/decodificador ya validado, así que no hay nada que reimplementar; la herramienta cierra el círculo en los dos sentidos:

  • Prueba de INFLATE — .NET comprime un corpus; el DecompressFile de Clarion tiene que reproducir los bytes originales.
  • Prueba de DEFLATE — CompressFile de Clarion escribe un .gz; .NET lo descomprime y confirma que coincide.
# generar los vectores dorados (caseN.bin + caseN.bin.gz/.zz/.raw + manifiesto)
dotnet run --project designer/CompressCore -- vectors ./vectors
# …que la app Clarion haga DecompressFile de cada .bin.gz y CompressFile de cada .bin a .bin.cgz…
dotnet run --project designer/CompressCore -- verify  ./vectors    # revisa la salida gzip de Clarion

El corpus recorre a propósito todos los caminos del código: vacío, un solo byte, texto largo compresible, series largas, binario con bytes NUL, datos aleatorios incompresibles y un búfer todo a ceros.

Class referenceReferencia de la clase #

Everything myCompress does lives in one class, CompressClass. This chapter is the full anatomy: how it's declared, the equates it ships, its lifecycle, and every public method with its parameters and return value.

Declaration

CompressClass CLASS,TYPE,MODULE('CompressClass.CLW'),LINK('CompressClass.CLW')
  • TYPE — a type, so you declare your own named instance (the template declares one global Zip). You could declare more for independent configurations.
  • MODULE/LINK — the engine compiles into its own object and links in automatically.
  • The .clw carries a bare MEMBER + module-level MAP (folds in BUILTINS.CLW and the kernel32 file calls). No external state — safe in multi-DLL apps and across threads.

Equates

EquateValueMeaning
Cmp:Raw0Raw DEFLATE — no header or trailer.
Cmp:Zlib1zlib wrapper — 2-byte header + Adler32.
Cmp:Gzip2gzip wrapper — 10-byte header + CRC32 + ISIZE.

Lifecycle

Construct runs automatically: it sets Level = 6, Format = Cmp:Gzip and builds the one-time tables (the CRC32 table, the length/distance base+extra tables, and the fixed-Huffman code table) via Init. Destruct frees the internal output buffer. Nothing else needs cleanup.

Public methods

Lengths are LONG; buffers are *STRING (passed by reference, never copied to bind). A negative return (or 0 from the file methods) means failure — read ErrText.

SelfTest() — Round-trips a known buffer through raw, zlib and gzip and checks the bytes return identical. Returns 1 on pass.

Todo lo que hace myCompress vive en una clase, CompressClass. Este capítulo es su anatomía completa: cómo se declara, los equates que trae, su ciclo de vida y cada método público con sus parámetros y su valor de retorno.

Declaración

CompressClass CLASS,TYPE,MODULE('CompressClass.CLW'),LINK('CompressClass.CLW')
  • TYPE — es un tipo, así que declaras tu propia instancia con nombre (la plantilla declara una global, Zip). Podrías declarar más para configuraciones independientes.
  • MODULE/LINK — el motor se compila en su propio objeto y se enlaza automáticamente.
  • El .clw lleva un MEMBER pelado + un MAP de módulo (que integra BUILTINS.CLW y las llamadas de archivo de kernel32). Sin estado externo — seguro en apps multi-DLL y entre hilos.

Equates

EquateValorSignificado
Cmp:Raw0DEFLATE crudo — sin cabecera ni cierre.
Cmp:Zlib1Envoltura zlib — cabecera de 2 bytes + Adler32.
Cmp:Gzip2Envoltura gzip — cabecera de 10 bytes + CRC32 + ISIZE.

Ciclo de vida

Construct se ejecuta solo: pone Level = 6, Format = Cmp:Gzip y construye las tablas de una sola vez (la tabla CRC32, las tablas de base+extra de longitud/distancia y la tabla de códigos Huffman fijos) mediante Init. Destruct libera el búfer de salida interno. No hay nada más que limpiar.

Decompressed data has trailing spaces / wrong lengthYou relied on LEN() or a padded STRING. Always carry the exact length returned by Compress and pass it to Decompress.
